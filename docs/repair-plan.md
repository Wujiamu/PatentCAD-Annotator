## 3. 统一行为契约

以下是任务包共同遵守的结果约束。需要变更时先交回协调者调整受影响任务，不能各包自行作相反选择。

1. **旧字节与恢复点优先。** 解析、备份、锁定、写入、回滚失败，不把有效旧字典当空数据写回。只操作当前目标的产品文件，保留完整属性；锁、临时文件和哨兵的路径须有明确归属。
2. **合法空字典与失败分开。** 完整对象根和合法空 entries 可以成功；空文件、顶层 null、错误根类型、截断及尾随垃圾失败。旧可选字段和未知字段继续按既有契约兼容，不顺手把所有 null／缺失字段改成错误。
3. **编号身份、显示、顺序分开。** 比较沿用 NumberIdentity 的去空白／忽略大小写；显示保留首次编号原文，编号仍是字符串。先保留获胜的原始命中，再按位置排序；统计使用未去重命中，粘贴／显示沿用去重视图。
4. **待裁决不是 modified_by 的反义词。** 已识别的未裁决备份必须持续可见；“稍后”允许查看和当前标注，但改名／改号／增删／粘贴等字典写回先要求裁决。Word 不用后一次备份覆盖未处理的恢复点。
5. **串行化产品写入，拒绝旧快照。** CAD 写回绑定原文档、路径、读取内容身份；Word 与 CAD 用同一个短持有锁协议覆盖读取检查、备份及替换窗口。原子替换负责文件完整性，不宣称提供 JSON–DWG 事务或阻止不遵守协议的第三方编辑器。
6. **改号失败必须说清结果。** JSON 与 DWG 不是统一事务；不能把 N 个成功掩盖失败对象，也不能无条件回写旧 JSON 进行“补偿”而覆盖较新的外部数据。重试须绑定原图纸并重新核对当前字典与旧号／新号。
7. **几何保持当前产品边界。** 不删除用户点链以躲过错误，不关闭穿字检查；不恢复 MLeader 自动 dogleg／landing。大括号仍为二维实体，保留恒定非零高程，不静默生成两套坐标或升级成三维系统。
8. **验证层级如实。** 静态、函数桩、源码导入、安装后黑盒、目标宿主分别报告；SKIP/BLOCKED 不是 PASS。本机不安装或探测四个旧 CAD 宿主，单列 GitHub 外部宿主验收。

## 5. 各任务包的可执行说明

### G01 — 修复测试运行器的成功条件（R-030）

- 目标：空程序集、全 Skip、不支持的测试形态不能变成 PASS。
- 最小改动：保留同步、无参实例 Fact 的当前用途。至少确认实际执行数；对 Task 返回、带参、静态或 Theory 等工具不支持的形态明确拒绝／SKIP 并返回非零，不静默忽略后输出整体成功。不新增测试框架或完整 xUnit 调度器。
- 反例／对照：net8.0 的零 Fact、全 Skip、异步失败或其他不支持形态，分别非零；一个同步 Fact 通过、一个断言失败时结果和退出码正确。不得拿 PowerShell Add-Type 默认目标运行时生成的 DLL 充当 net8.0 反例。
- 交付：最小运行器补丁、对应负对照、准确标注支持子集的脚本输出。通过后由协调者分发运行器快照，其他包不再修改它。

### G02 — 一次修好解析、计数与编号身份（R-016／017／018／021／032／033）

- 入口：Patterns.ExtractAll → DictModel.BuildModel；C# Preprocess → ExtractMarkingSection → ExtractAll；调用方还有 CAD 粘贴预览、现有解析契约和 VBA 语料工具。
- 实施次序：先确定完整编号词法和获胜区间 → 用真实引擎处理段落／行边界 → 按原文位置稳定排序 → 用原始命中统计 → 在展示／粘贴边界去重。名称频率相同时取原文首次命中，而不是规则批次中的首次命中。
- 编号身份按消费端规则归组；同号不同名进入同组 conflicts，保留首次编号拼写和候选原文。范围限支持的 ASCII 字母数字编号，使用可对照的归一化键／比较；不能只凭本机 CompareMode 的区域设置推定与 OrdinalIgnoreCase 等价，也不全局改变名称比较规则。
- 保留当前 ExtractAll 展示／粘贴的去重契约；为统计提供必要的原始命中通路，不能让新增重复条目流入字典。API 采用最少入口，不引入通用解析框架。
- 正则以实际 VBScript 和 .NET 语义为准，文末表达式允许两端不同；裸列表限定行内空白，保留空格、Tab、CR／LF／CRLF 和 Word 表格预处理。
- 矩阵：编号在前／后、括号／表格；S1、10-1、123A1、超长度；混排顺序；重复同名、同号异名、大小写同号、频率平手；Z形支架；空段／句号；孤立文字加下一行数字。先保留原反例红灯，再跑两个真实引擎；Word BuildModel 的 occurrences／name／conflicts 另做 L2，不能只回放消费者。
- 测试归属：本包专用 G02 解析测试及语料。修改 MarkingTextParserTests、ParserContract／Corpus 的预期必须给出独立业务期望；不能直接把新实现输出覆盖成 expected。不改 AutoExport、CAD 编解码或最终部署副本。

### G03 — 文字末端、旧 Leader 对齐与测量（R-001／015／020）

- 调用方复核重点：PatLeaderTextAttachment 的路由与四版 PatMLeaderCreator 都调用 PatTextPathRouting.Route。2007 现场是首个证据，不是将共享改动限制为单版验证的理由。
- 先修 R-001：区分用户拐点和程序生成的文字侧末端；缩进、真实文字范围和避让扩展边界要使用相容的约束。禁止靠移除用户点、无条件放行末端或降低全部碰撞检查来过测试。
- 再合并修旧 Leader：一次读取关联 MText 的字高／可用宽度／附着角；对齐后根据稳定拐点与新位置重算附着角并设置 Location、末端。MText 属性设置顺序须保持用户指定的新位置，原生 Annotation 与扩展字典关联均兼容。不可读时沿用有诊断的估算，不扩建排版引擎。

- 版本：Shared 原码单处修改；MLeader 命令在明确源版修改后由协调者同步四版。保持点链、末端缩进和关闭自动 landing／dogleg 的契约，检查实际末顶点及记录点链一致。
- 交付：每项独立红绿用例、失败契约、对应版编译和 API 证据。共享更改覆盖五版构建／相关模拟；真实 2007/2010/2013/2015 行为列 GitHub 外部宿主验收，2025 组也需真实 CAD 路径确认，模拟不当作替代。

### G04 — JSON 严格读入与保真写出（R-002／019）

- 旧解析器：要求正确标点、完整闭合和消费完整输入；未知／非法转义不能吞字符。合法反斜线、引号、斜杠、b/f/n/r/t/u 读值正确；U+0000–U+001F 生成合法 JSON。
- 五版加载器：拒绝顶层 null 和错误根类型；无效模型不替换有效缓存、Diff 或恢复目标。不要把“严格 JSON”扩展为一刀切禁止缺少 metadata／warnings 等旧可选字段；未知字段兼容、条目归一化规则先按现有契约保留。
- 输出格式保持 UTF-8 无 BOM、现有 CRLF／缩进／键序及 `"modified_by": "cad"` 识别格式。内容字符串 CRLF 的规范化与文件行尾分开测试；优先合法值保真，不顺带重排所有版本的 JSON。
- 对照：损坏语法／截断／空文件／错误根／尾随垃圾／null 失败；合法空字典和旧可选字段缺失成功；逐字符转义往返；严格解析器校验生成结果。必须使用真实 2007/2010 SimpleJson，不能只测 2025 序列化器。
- 恢复反例：损坏备份进入 ResolveRestoreCad 后，当前 JSON、备份字节、属性不变，错误可见。该包覆盖解析前置条件；备份生命周期／版本与锁接口由后续 G05 完成。
- 交接：向 G05 提供加载失败语义、合法空值契约与序列化输出样本。此后本包停止修改 DictEntry／DictWriter，避免覆盖 G05 的内容身份和写入门禁。

### G05 — 统一字典写入、备份裁决、输出基线和 Word 开关（R-003／005／006／009／010／013／023）

这是跨端协议包，必须由一个责任 Agent 连续完成分阶段变更；不要再拆给多个 Agent 同时修改 AutoExport、DictConflict 和写回接口。

**5.1 先建立同一读取身份，覆盖全部写入口。**

- 加载模型、内容身份来自同一份读取字节，键绑定完整字典路径；保留按图纸／路径的已有隔离。不要先对 A 取哈希，再读取 B 却声称模型属于 A。
- 2 秒轮询比较内容身份，相同内容不重新反序列化；同时间戳、同长度内容变化仍发现。NotifySelfWrite 记录成功写出的身份，清理自己的 Diff 基线，保留 Removed 与 PATCHECK 刷新逻辑。
- 编辑／新增／删除／粘贴／恢复 CAD 等写回都携带打开时的路径、文档和身份；目标不存在也有明确的“原先不存在”状态。原目标变化或切换时拒绝静默覆盖，保留用户输入和有效旧模型，要求重载／裁决。
- 接口放进现有 DictLoader／DictWriter／DictFileVisibility 工作流，不另建同步服务。列完所有调用方后才能取消旧的无条件写回通道；纯序列化接口仍可供测试使用。

**5.2 补上产品写入互斥，不把“写前哈希”说成事务。**

- 推荐同目录、按完整字典路径唯一的短持有文件锁，例如 `<字典路径>.patlock`。CAD 用 OpenOrCreate 的 FileStream＋FileShare.None；VBA 用等价的排他 Open／Lock，先在隔离文件验证两个运行时确实互斥。
- 由顶层写操作持锁，覆盖读取版本检查、备份、临时写入、替换与成功状态更新；内部写函数不重复取得同一锁。Word 也必须参与，不能只修 CAD。锁文件存在不等于锁被占用，释放句柄才是解锁；不删除公共锁路径，不做僵尸锁巡检服务。
- 已有路径普通保存拿不到锁／备份失败时，沿用导出失败并取消该次普通保存的语义；CAD 迅速返回可重试的忙状态。用有限等待和清晰诊断，不无限阻塞 UI。
- 必测 A 读→B 写→A 保存，以及“版本检查后、替换前”插入另一产品写入，验证同一锁覆盖窗口。第三方编辑器不遵守锁的情况保留残余限制；不得宣称任何外部写入都可阻止。

**5.3 在同一个状态机中保护待裁决恢复点。**

| 初始状态 | Word 导出／CAD 写回的统一处理 |
|---|---|
| 无备份，当前含 CAD 修改 | Word 持锁复制并确认备份成功后才写新 JSON；复制失败保留所有旧文件／属性 |
| 已有待裁决备份，当前与已知输出基线一致 | 后续正常 Word 导出保留冻结备份并更新输出基线；CAD 字典编辑先要求裁决，不因新 modified_by 状态隐藏提示 |
| 已有待裁决备份，当前又含 CAD 修改或来源不明 | 不以新备份替换旧恢复点；若不是原冻结内容，停止导出并提示先裁决，保留两个现有版本 |
| 已有待裁决备份，可见当前文件偏离输出基线 | 按真实磁盘变化／未知来源保护；不覆盖当前文件或原备份，提示先裁决，而不是再生成快照并删除旧恢复点 |
| 用户选择稍后 | 备份和待裁决提示持续存在；查看／当前标注可用，字典写回入口受门禁 |
| 用户明确采用 Word／恢复 CAD | 在相同版本／锁协议下执行；恢复先用 G04 验证，再写成功后清理对应备份，失败保留可恢复数据 |

- R-005 的最小改法是**不覆盖未处理的已有备份**。先保留当前文件名与 FindWordBackup 识别规则，不为了同秒重入新增后缀协议。若实际测试证明同一状态必须保留多份快照，再由本包同时调整写方／读方／排序；不能由 Word、CAD 各自改名。
- 发现多份历史备份时保留并报告，不自动删除除“最新”以外的文件；按用户明确裁决逐份处理，不建设长期版本管理界面。
- R-003 直接停止自动删除旧 Word 主名字典，保留原字节和属性并给出路径诊断。新目标成功不再当作旧文件可以丢弃的证明；不新增“推测所有权后继续删”的复杂系统。
- 上表的“来源不明”不能由“磁盘内容与本次 Word 新导出不同”直接推定，否则会把 R-006 变成普通保存阻断；按下节已知输出基线判定。

**5.4 用现有比较逻辑维护最小输出基线（R-006）。**

- 基线按字典完整路径保存最近一次已知成功输出的摘要，而不是本次待写内容。产品专属同目录文件 `<dictPath>.word-baseline` 使用固定产品／版本头和 SHA-256 摘要，不存字典正文；只读写可确认归属的文件，不覆盖同名未知对象。新文件的 ACL 默认可能继承目录而宽于已有字典，因此不得先创建明文快照再补 ACL。
- 复用 NormalizeJsonForExportCompare 的时间戳／换行规范化，对结果的 UTF-8 无 BOM 字节计算 SHA-256，与基线摘要比较。VBA 调用系统内置 CryptoAPI，CAD 使用平台 SHA-256，不自写哈希算法或引入外部运行时库；两个实现必须以中英文、时间戳与 CR/LF 样本证明摘要一致。磁盘仍等于基线而 Word 内容变化不触发外部编辑备份；磁盘偏离基线则保护当前文件，既有 CAD 修改标记仍优先触发备份。
- 成功 Word 导出后，用同一写锁原子更新基线文件；明确采用 Word／恢复 CAD 的裁决后也把已确认的当前内容记成基线，避免刚裁决完就再次误报。普通 CAD 修改仍以现有 CAD 标记表达，不假装是 Word 成功输出。路径切换后分别维护，旧文件和基线不自动清理。
- 首次升级无基线、损坏／不可读基线、基线更新失败或进程在两个文件更新间中断时，按“基线未知”保守保护并明确诊断，不断言确有人手工编辑。基线只是检测辅助：更新失败不能冒称已回滚成功写出的 JSON；要如实显示字典已导出、基线不可用，下次进入保守保护路径。不宣称 JSON 与辅助基线是两文件原子事务。
- 必测健康路径“只改 Word”同进程及重启后不出现伪冲突；“只改可见 JSON”“两边都改”仍保护；已有待裁决备份时的正常 Word 连续保存不被误拦截。另测裁决、切换路径、无／坏基线、基线 I/O 故障及崩溃窗口，断言任何原恢复点和未知文件不被删除。异常情况下的保守提示是明确的剩余限制，不能包装为完全消除误报。

**5.5 同进程显式关闭必须保留。**

- 区分首次／失败待初始化、已启用、用户关闭的状态；重开面板不覆盖用户关闭。手动重新勾选可启用；进程重启与 VBA Reset 按现有启动策略另验，不新增注册表偏好。
- 保留 run ID、钩子诊断与保存事件入口，不能靠取消 AutoExec 或面板初始化绕过既有放行门。

**测试与交接：** 为以上五阶段各保留原反例及状态矩阵；先做可控 I/O 和锁交错，再做真实 VBA L2、隔离安装及同一候选包的安装后黑盒。覆盖可见／隐藏、只读／锁定、中文空格路径、首次／普通保存／另存为、同秒重入、稍后后各写入口、多文档。源码完成不等于全部宿主关闭。G06／G07 只在本包接口、调用迁移和回归集成后开始。

### G06 — 改号失败结果与显式重试（R-004）

- 复用 G05 的版本、锁及待裁决门禁；捕获请求文档，后续不能按另一个 ActiveDocument 写图。
- 底层 setter／遍历返回或传播“匹配、实际更新、失败对象及原因”，不要把异常折算成 0 或普通成功数。无匹配与有匹配但失败分别报告。
- 最小一致性策略：同一次 CAD 改号用一个事务，任一目标写失败则回滚本次 CAD 更新；回滚时实际提交数为 0，不能把曾尝试成功的数量报告成已更新。若 JSON 已成功保存，明确显示“字典已改，图纸未完成”，保留旧号／新号、图纸身份和失败对象，提供针对该操作的显式重试。不能仍显示完整同步成功，也不自动回写旧 JSON。
- 对话框／协调入口只有在结果已展示、可保存失败信息和重试参数后才结束流程；不能依赖已经销毁的条目对象。重试重新核对图纸、字典版本和仍属 PAT 的旧号对象；名称修改不改图纸、删除字典项不删除实体。
- 必测：同号两处、一处受控拒写；无匹配；setter 失败；事务提交失败；JSON 写失败；重试前字典／图纸变化；同号多处全部成功。不因普通 CAD 文字同号而改它。
- 最终结论保留“两个存储不是原子事务”的边界。只有错误报告、缓存状态及重试实际走通，才关闭本项；仅新增一句错误日志不够。

### 如实记录的局限

A→B 交错本身无法在 L1 用真实加载器确定性复现——它要求文件在两次读取之间改变，单线程做不到。我一度写了两条试图确定性复现的单元测试，实测**修复前后都通过**（它们断言的是底层 `LoadBytes` 与 `Load` 的差异，而非 `ReadSnapshot` 行为），已删除，未留在仓库充当假绿灯。缺陷捕获证据是复核者的钩子探针（在证据副本内注入时序）；生产侧证据是修复后等价断言与 `ReadSnapshot` 语义一致。
