# v4.0 计划：CAD 端字典编辑与识别（实施计划）

> 本文档为 v4.0 功能的**实施计划**，与 `docs/development-log.md`（变更记录）、`docs/version-plan.md`（版本规划）配套。
> 计划跟踪方式：执行时按阶段推进，每步完成后更新下方「阶段状态」勾选；执行期间如有偏差，先更新本计划再继续。

## 目标

在 CAD 端直接编辑 `.dict.json`，形成「Word 导出 → CAD 使用 → CAD 端手动修正 → 回写」的完整闭环，并同步到全部 5 个版本与部署包：

1. **粘贴识别**：从 Word 复制附图标记段落，CAD 端解析为编号+名称条目（复用 VBA 识别引擎逻辑）
2. **编辑对话框**：改编号 / 改名称 / 新增 / 删除单条条目
3. **冲突裁决**：检测外部（Word 端）修改，备份后弹窗裁决采用 CAD 修改还是外部修改
4. **实体联动**：条目编号修改后，图纸内旧编号文字一并更新 + Regen
5. **VBA 备份逻辑**：Word 端导出前对旧字典文件做备份，防止 CAD 端修改被静默覆盖

平移要点补充（实际执行记录）：
- 编译命令：`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe <csproj> /tv:4.0 -p:Configuration=Release`（不加 /tv:4.0 时回退到 C# 2.0 编译器，无法识别 var/对象初始化器）

- 降级修复：`out int x` 内联声明 → 先声明后传参；自动属性初始化器 `{ get; set; } = ""` → 手动字段 + 属性
- PatEntityHelper.cs 补 `using System;`（新代码用 StringComparison）
- 共享 10 个 .cs 文件 2007/2010 SHA256 全部一致

平移要点：
- 2007 版目标 .NET 2.0，**禁用 LINQ**；2010 版 .NET 3.5 可用 LINQ
- JSON 库使用 SimpleJson（零依赖，与部署包现状一致），需实现 Newtonsoft 用到的序列化特性
- 标注 API 为 Leader + MText，与 MLeader 组无关的改动照常同步

## 跨版本同步规则（来自 AGENTS.md）

- 功能逻辑 / 字典格式 / 面板行为类变更 → 同步全部 5 个版本
- 仅特定版本 API 适配（MLeader vs Leader）→ 不必同步
- VBA 模块或部署包脚本修改 → 同步 5 套部署包（或逐套说明差异）
- 2007/2010 同用 Leader，2013/2015/2025 同用 MLeader，组内代码逻辑一致

## 已知风险

- 2013/2015 的 MSB3274 规避：HintPath 需指向 `lib/net35`（v3.2 已验证方案）
- 2010/2007 无 Newtonsoft 可用，SimpleJson 需覆盖 `SerializeObject`/`DeserializeObject` 及属性特性用法
- 2007 版无 LINQ：`List.Find`/`ConvertAll` 等需手写循环
