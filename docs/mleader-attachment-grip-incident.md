# MLeader 额外附着点问题总结

## 结论

2013、2015、2025 版本不再使用 MLeader 创建新的专利附图标记，统一改为与 2007、2010 版本相同的 `Leader + MText` 组合。

这不是因为 MLeader 不能创建引线，而是因为 MLeader 的文字内容附着机制会在用户指定的引线顶点之外，产生一个连接文字的附着几何。该几何在 AutoCAD 中表现为额外的蓝色夹点或额外线段，无法通过现有 API 设置稳定、彻底地关闭。

## 现象

用户在三点模式或无限点模式下依次点击附着点、拐点和文字位置，预期结果是：

1. 图中只保留用户点击的引线点；
2. 文字保持水平；
3. 移动文字后，引线不应被文字附着点重新拉弯。

实际结果是：

- 用户点击的点都能被正确接收，但文字附近出现额外的附着点；
- 引线会从最后一个用户点继续吸附到标注文字，形成不必要的弯折或短线段；
- 在部分 AutoCAD 版本中移动标注文字后，文字可能出现倾斜；
- 该现象同时出现在三点模式和无限点模式，也出现在 AutoCAD 2013 及 AutoCAD 2025 的实测环境中。

## 日志证据

问题日志位于：

`PatentMarker-2025-deploy/PatentMarker.log`

日志中记录了每次标注请求的用户点和 MLeader 实际几何。典型记录显示：

- `leaderLineCount=1`；
- `lastVertex` 与用户请求的最后一个引线点一致；
- 代码没有额外调用 `AddLastVertex` 写入那个可见的附着点；
- `textLocation` 位于引线文字侧，并形成了 MLeader 文字内容的连接几何。

因此，问题不是三点模式或无限点模式在采集阶段多读了一个点，也不是代码循环多添加了一个顶点。用户点列表本身是正确的，额外的可见点来自 MLeader 的文字内容附着关系。

## 已尝试的 MLeader 修复

在保留 MLeader 的方案中，曾对以下方向进行调整：

- 关闭自动 dogleg；
- 关闭 landing；
- 关闭 leader 到文字的自动延伸；
- 调整文字附着方向和附着位置；
- 强制 MText 旋转角为 0，尝试保持文字水平；
- 调整 MLeader 创建顺序，先创建有效的 MText、文字位置和样式，再添加引线顶点。

这些调整解决了部分版本中的“引线不显示”和“文字倾斜”问题，但不能稳定消除文字侧的附着几何。尤其是水平文字附着时，MLeader 仍可能保留连接文字所需的 landing 或附着段。不同 AutoCAD 版本对这些属性的显示和编辑行为也不完全一致。

## 为什么舍弃 MLeader

### 1. 它无法满足“可见点必须等于用户点击点”的要求

MLeader 的顶点数量和文字内容附着几何不是同一个概念。即使 `lastVertex` 与用户最后点击点一致，文字内容仍可能拥有自己的连接点和夹点。因此，仅从 `AddLeaderLine`、`AddLastVertex` 或点采集代码入手，无法保证屏幕上只出现用户指定的点。

### 2. 关闭自动行为没有跨版本的可靠保证

MLeader 提供了多个 dogleg、landing、文字附着和方向属性，但它们之间存在联动。某个属性在一个版本中隐藏了线段，在另一个版本中仍可能显示文字附着段，或者在移动文字后重新生成连接几何。

### 3. MLeader 会影响文字移动和方向

MLeader 把引线、文字内容和文字附着关系封装在一个对象中。用户调整文字位置时，AutoCAD 可能重新计算附着方向，导致引线变形，甚至让文字出现倾斜。专利图纸标注要求文字始终水平，这种隐式重算不适合作为默认行为。

### 4. 2007/2010 的方案已经满足需求

`Leader + MText` 将引线和文字拆成两个普通实体：

- `Leader` 只保存用户指定的引线点；
- `MText` 单独保存文字位置和内容；
- 文字旋转角可以明确设为 0；
- 不存在 MLeader 的文字内容附着夹点；
- 2007 至 2026 可以采用一致的几何语义。

在当前需求下，稳定性和可预测性比使用单一的 MLeader 对象更重要，因此选择回退到这个方案。

## 当前实现

2013、2015、2025 版本已经同步完成以下调整：

- `PATMARK` 使用 `Leader + MText` 创建三点和无限点标注；
- `PATCHECK` 识别 `Leader` 及其关联的 `MText`；
- `PATALIGN` 只调整关联文字的 `MText.Location`；
- `PATSELECTALL` 同时选择引线和关联文字；
- 字典面板删除标注时同时删除 `Leader` 和 `MText`；
- 字典编号重命名时同步更新关联 `MText`；
- 所有版本的标注文字强制保持水平；
- 五个版本的部署 DLL 已重新编译并同步。

VBA、Word 附图标记识别逻辑和 JSON 格式没有因为本问题而改变。本问题发生在 CAD 实体创建和编辑层，不是 JSON 解析或 VBA 导出层的问题。

## 兼容性说明

旧版本已经创建的 MLeader 不会自动转换为新的 `Leader + MText`。当前 2013/2015/2025 版本的新标注和相关管理命令以 `Leader + MText` 为准。

如果图纸中仍有旧版 MLeader 标注，建议在切换后重新创建对应标注；不要把新旧两种实体混合当作同一种标注处理。后续如果确实需要旧 MLeader 的自动迁移，应单独设计迁移工具，而不是在常规标注命令中隐式转换。

## 验证结果

本地已完成以下验证：

- 2007、2010、2013、2015、2025 五个版本均成功编译；
- 2010、2013、2015 运行时模拟测试均为 5/5；
- 2025 测试套件为 106/106；
- 五个版本的 AutoCAD API 契约检查通过；
- 版本结构和静态同步检查通过；
- 2013、2015、2025 源码中已不再使用 MLeader 创建路径。

上述验证没有替代真实 AutoCAD 界面中的最终交互测试。实际部署后仍应在对应 AutoCAD 版本中重新加载 DLL，分别验证三点模式、无限点模式、移动文字和删除/重命名标注。

## 后续重新评估条件

只有在确认目标 AutoCAD 版本提供了可靠的 API，能够同时满足以下条件时，才有必要重新考虑 MLeader：

1. 文字附着不会产生额外可见夹点或线段；
2. 最后一个用户引线点不会被文字连接几何改写；
3. 移动文字不会改变文字水平状态；
4. 三点模式和无限点模式在所有支持版本中表现一致。

在满足这些条件之前，`Leader + MText` 是本项目更可控的实现方案。
