# 问题记录：2007 版大括号方向（2026-09-04）

> 状态：**已定性，修复已实现并重打包；待 AutoCAD 2007 现场目检。**
> 真实截图证明当前几何本身错误，并非现场加载旧 DLL。

## 1. 当前问题摘要

- **可直接从截图确认的现象**：端点在同一竖轴，中部尖点在右侧，但上下两段直干跑到端点轴线左侧，整个轮廓跨轴，中心形成异常狭长楔形。截图本身不包含第三次点击标记，因此不能仅凭图片判断“尖点是否与点击侧相反”；可以确定的是轮廓不应越过端点轴线。

- **根因**：`PatBraceGeometry.BuildPoints` 使用 `stemOffset = -tipOffset * 0.42`，把直干放到了尖点反侧。测试 `WidthPointControlsCenterTipAndOppositeOuterShoulders` 和 `CenterTipIsSharpAndStemsStayOppositeTheTip` 又把该错误行为写成了通过条件。

- **结论**：这是当前共享几何的真实 bug，影响全部五个版本；2007 只是首先被现场发现。

## 2. 已核实的事实（本机仓库）

| 项    | 结果                                                    |
| ---- | ----------------------------------------------------- |
| 真实截图 | 端点轴线约 `x=369`，直干约 `x=179`，尖点约 `x=820`                 |
| 截图比例 | `(369-179)/(820-369) ≈ 0.421`，精确对应源码的反向 `0.42W`       |
| 共享源码 | `stemOffset = -tipOffset * 0.42`，会生成总跨度 `1.42W` 的跨轴轮廓 |
| 旧测试  | 28/28 通过，但其中两个测试明确要求直干位于尖点反侧，因此属于错误规格，不是无 bug 的证据     |

## 3. 为什么 AutoCAD 2026 的旧版本曾经正常

- `cad-plugin/Shared/` 是**编译时共享源码**，不是五个 AutoCAD 在运行时共同加载一个程序集。每次打包时，2007 与 2025 项目会分别把当时的共享源码编译进各自的 `PatentMarker.dll`；因此不同日期安装的 DLL 可以包含不同代的几何，即使项目结构一直写着“共享源码”。

- Git 历史给出了完整时间线：

  - `1cda5a6`（2026-08-12 13:43）把直干设为 `+0.5W`，轮廓全部位于尖点一侧，并在同一次提交中重建了 2007/2025 部署 DLL；这一代可解释 AutoCAD 2026 中看到的正常形态。

  - `9098e82`（2026-08-12 15:49）把共享几何改成 `-0.42W`，并同步修改测试去接受反侧直干，但该提交没有重建部署 DLL。

  - `1cf78c4`（2026-08-12 17:39）随后重建了各部署 DLL，从此新打包的 2007/2025 DLL 都带入 `-0.42W` 回归。

- 文档所称的 v5.1 “AutoCAD 2026 全量实机测试”实际覆盖 PATDOCTOR、BZM、BZC、PATALIGN、BZS、PATMLVERIFY 与保存重开，清单中**没有 PATBRACE**。因此该记录不能证明回归后的 2025 DLL 在 AutoCAD 2026 中仍能正确画大括号；HTML Demo 中的大括号则是独立 SVG 路径，也不是插件实体测试。

- 所以，在相同提交、相同三个输入点与默认 WCS 下，2007 和 2026 应生成同一组大括号顶点。当前没有证据表明 AutoCAD 2007 会把正确顶点翻转；截图反而精确复现了后来共享源码的 `0.42W` 参数。2007 是首先暴露回归的宿主，不是已证实的回归来源。

## 4. 现场证据与旧结论为何错误

- BZD（PATDOCTOR）报告（生成于 2026-09-04 08:48:43）显示实际加载的 DLL：
  `D:\我的文档\桌面\PatentCAD-Annotator-master\PatentCAD-Annotator-master\PatentMarker-2007-deploy\PatentMarker.dll`
  路径含双层 `…-master\…-master\`，为 GitHub "Download ZIP" 解压的典型结构。

- 用户确认：**这一份 zip 就是最新版**。

- 真实截图轮廓与当前参数模型逐项吻合，尤其是 `0.42W` 的反向直干偏移。这消除了“新版 DLL 理论上不应反向”的矛盾：新版 DLL 恰好就是产生该轮廓的版本。

- 先前只验证“尖点在第三点所指侧”，却错误地把“肩/直干在另一侧”当作 PPT 特征；测试和文档重复了同一个错误假设，不能相互独立地证明实现正确。

## 6. 已实施解决方案

1. 按 DrawingML/PPT `rightBrace` 的包围盒语义重建轮廓：端点偏移 `0`、直干偏移 `0.5W`、尖点偏移 `W`，所有点均在点击侧。
2. 四个转角使用四分之一椭圆；沿高度半径为 `min(W,H) × 8333 / 100000`，以 8 段三次贝塞尔采样保持旧 AutoCAD 兼容。
3. 测试改为断言完整轮廓不跨端点轴线，并增加 PPT 默认比例断言。
4. 共享源码同步影响 2007/2010/2013/2015/2025，五套部署 DLL 已重新编译和打包。

当前 2007 部署 DLL（包含 `PATBRACEEDIT` 原位重建修复）：`135168` 字节，SHA256
`65181990AC1129A1463EC2B2AC2B01200E1B74DD0B3B3929D5C2C600F6700614`。

几何基准：ECMA-376 DrawingML 预设形状 `rightBrace`；其公开预设定义可在
[LibreOffice 镜像](https://github.com/LibreOffice/core/blob/master/oox/source/drawingml/customshapes/presetShapeDefinitions.xml#L14745-L14820)
和独立的 [docx4j 镜像](https://github.com/plutext/docx4j/blob/master/docx4j-core/src/main/resources/org/docx4j/model/shapes/presetShapeDefinitions.xml#L15302-L15377)
交叉核对。
