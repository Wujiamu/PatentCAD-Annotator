# 修复任务包协作与上下文留痕

适用于 [修复计划](repair-plan.md) 的当前任务包；G24–G27已有实施记录，当前仅第14节G28，不再安排这些历史包并行写入。文件范围、业务契约和验收要求沿用计划；这里只补充交接与上下文约定。

## 多个 Agent 同时工作

**分派基线必须包含当前工作树。** 本项目已有未提交和未跟踪的生产代码，HEAD 相同不代表任务起点相同。协调者按原计划提供同一工作树快照；本包补丁相对此快照生成，不能把整份 `git diff HEAD` 当作自己的改动。

**共享文件交接按集成结果放行。** 前置 Agent 说“完成”不等于后继可以开工；协调者集成相关接口及回归后，给出后继应使用的快照引用。已完成的历史交接不重复执行，以计划中当前待处理包为准。

| 交接 | 后继需要拿到的内容 |
|---|---|
| G04 → G05 | 五版 DictEntry／DictWriter 的集成版本；无效输入、合法空字典、转义与旧字段兼容的实际约定及回归入口 |
| G05 → G06 | EditEntryDialog／DictPaletteControl 的集成版本；写回接口、版本检查、锁与待裁决门禁的使用方式 |
| G05 → G07 | PatSettings.cs 的完整集成版本；保留其中原子 I/O 与锁实现，再修改设置归属 |
| G16 → G17 | DictPaletteControl.cs 的恢复入口集成版本；恢复坏当前文件使用的快照不能被当成普通编辑／改号可用的新模型身份 |
| G20 → G21（历史） | Control 的裁决动作条件集成版本与四格回归；G21 保留此入口，再收敛单槽待同步记录的编号编辑守卫，不能从 G17 旧文件覆盖回来 |
| G24 → G25（历史） | 提交快照来源、规范字典路径/真实模型校验、每图纸重试UI刷新及集成引用；G25据此刷新部分成功后的面板，不改回全局确认位或缓存路径 |

后继只读分析可提前进行，共享文件的实施等上述交接。源码交接与宿主放行分开：相关源码集成及自动回归可支持后续开发，四组旧 CAD 的 GitHub 外部验收另记，不能据此前置条件把旧宿主变成本机待办。

**公共文件和产物只保留一个写入者。** 测试 csproj、公共桩／夹具、Strings.cs，以及部署副本、dotm、同步结果和总清单由协调者整合。任务 Agent 如需改动，提交具体补丁需求；源码归属仍按原计划，不因不同任务只改同一文件的不同段就并行写入。Word/CAD 的桌面操作和实际安装另由协调者安排串行时段，避免共用 Startup、模板或实例。

**契约变化只通知受影响包。** 例如 G05 改写回签名或锁／基线文件约定，交接消息写明“旧约定 → 新约定、受影响文件、需要等待的包、可用快照”。协调者回填原计划，受影响包再接续；其他不依赖该变化的包继续工作。任务 Agent 不自行改另一包来适配，也不再建立一份平行任务总账。

## 单个 Agent 留什么

每个开工包使用一页 `docs/repair-work/Gxx.md`，由该包当前负责 Agent 更新；接手时在同页更换负责者。开工时再创建，不预建 14 份空记录。派发归属和集成结果由协调者在原计划任务表登记。

便笺只保留能让另一个 Agent 脱离聊天接续的信息：

```text
# Gxx — 当前负责 Agent／会话标识

基线：工作副本路径；工作树快照引用；已集成的前置包版本。
本包改动：相对该基线的补丁／提交／文件差量位置。
契约差量：与计划不同或新增的行为／接口、原因、影响的后继包；没有则省略。
已排除方案：仅保留会导致重复试错的方案及排除依据；没有则省略。
证据入口：反例／修复后报告位置、精确选择器及其对应源码／候选引用。
续接点：停在哪个具体函数／用例；下一步动作；如在等交接，写明等谁提供什么。
交接结果：实现交付引用；协调者确认的集成引用；独立验收引用或未完成范围。
```

证据入口引用项目已有报告、findings 或产物，不在便笺复制整份日志、哈希表和验收矩阵；也不能只写“见聊天上文”。“实现交付”“已集成”“独立验收”分别记录，避免下一位把作者自测当成已验收。

在契约决定变化、依赖交接、验证结论变化，以及暂停／交班／上下文切换前更新该页。保留当前结论和必要的排除依据，不写逐命令流水账。尚未结束的运行附会话／进程或运行目录及归属，便于接手者接续或清理本包资源。

接续所需材料限定为：本页、原计划对应任务包、所引用的补丁与证据。若便笺基线与协调者新集成版本不同，先记录需要迁移的本包差量；旧版本的 PASS 留作历史证据，不标成新快照已通过。
