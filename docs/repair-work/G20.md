### 2.1 最小改法逐条对应计划 §12.3

| 计划要求 | 落地 |
|---|---|
| 不以备份能否解析决定整个对话框能否打开 | 删掉入口的 `!selection.BackupParsed → return` |
| `CurrentParsed` 约束「采用 Word 版」 | `IsActionAvailable(sel, KeepWordAction) == sel.CurrentParsed` |
| `BackupParsed` 约束「恢复 CAD 版」 | `IsActionAvailable(sel, RestoreCadAction) == sel.BackupParsed` |
| 两者均坏时给明确原因并保留「稍后」 | `_lblReason` 显示两条原因；「稍后」永不参与可用性判断 |
| 采用当前版本仍由用户明确选择，不能自动删坏备份 | 无任何自动动作；`G20_NoActionLeavesBothFilesUntouched` 固定 |
| 确认阶段继续执行原文档／路径、双身份和短时产品锁检查 | **未触碰** `DictConflict.ReadSelected`／`AcquireLock`；`G20_*ChangedAfterCapture*` 复验 |

### 2.2 为什么不用「打开对话框时按动作禁按钮」就够

只改 `ArbitrateDialog` 的按钮状态是不够的：入口 `return` 发生在 `new ArbitrateDialog(...)`
之前，按钮从未被构造。两个文件都必须改，这也是计划把两个文件都列进范围的原因。

### 2.3 兼容入口不预置解析结论

`ArbitrateDialog(string dictPath, object document, string identity, string backupPath, string backupIdentity)`
只拿到身份字符串，不知道两端能否解析。若照旧用 `CurrentParsed`（默认 false）禁用按钮，
这个入口会变成「两个按钮永远不可用」。因此新增 `_parsedStateKnown`：只有走
`ArbitrateDialog(RecoverySelection)` 时才按快照预置，兼容入口交给动作入口按磁盘字节判定
（`KeepSelectedVersion`/`RestoreSelectedBackup` 本来就会复核）。生产代码只有
`DictPaletteControl.cs:672` 一个构造点，走的是 `RecoverySelection` 入口。

### 4.2 与封存探针的两处差异（必须说明）

1. **封存探针不能在修复后重放完成。** `palette-probe/Review.cs` 反射调用
   `BtnArbitrate_Click` 后立刻读 `_lblStatus`，没有消息泵。修复前坏备份那一格事件提前
   `return`，所以它「跑得完」并记下 FAIL；修复后事件正常打开**模态**对话框，探针自身不驱动 UI，
   于是阻塞（`green-sealed-probe-blocked.txt` 记录 25s 超时后终止，停在
   `valid-current-invalid-backup-fixture` 之后）。这是探针的驱动方式限制，不是产品失败，
   也不能当作修复后 PASS。本包探针用 `Application.OpenForms` + 真实按钮驱动同一批业务判定。
2. **封存探针的 bad-current 格子不经过面板入口**（直接调 `RestoreSelectedBackup`）。
   本包探针每一格都走 `BtnArbitrate_Click` → 模态对话框 → 按钮，层级更高。

两版的 26 条断言文本与判据完全一致。

## 9. 残余风险

1. **`_lblReason` 的版面是估算的。** `ClientSize` 216、`_lblInfo` 高 70、`_lblReason`
   从 y=84 起高 50、按钮在 y=176。若某语言下原因文本换行超过 3 行会被裁掉。
   未目检（§8.2）。缓解：原因文本最多两行（每行一个动作 + 一句固定英文常量）。
2. **原因文本是英文常量 + 中文按钮名。** `DictConflict.CurrentUnparsableError` 等是
   英文硬编码（G16 引入，本轮不改 `Strings.cs`）。英文界面下一致；中文界面下是
   「采用 Word 版: Current dictionary cannot be parsed.」。这是既有措辞，不是本包新增。
3. **兼容入口的两个按钮现在默认为可用。** 走 `ArbitrateDialog(string, object, string, string, string)`
   的调用方不再得到「坏当前则采用禁用」的预判，改为点击后由动作入口返回错误。
   生产代码没有这种调用方（唯一构造点走 `RecoverySelection`），但外部/未来调用方需要知道。
4. **`DescribeUnavailableActions` 用 `action` 字符串而非枚举。** 与项目里
   `RequestPanelCommand(doc, "PATCHECK")` 的风格一致，也避免给 Shared 增加新类型
   （新类型要改五个 csproj，越界）。代价是拼错的动作名静默返回 `false`。
5. **`IsActionAvailable` 只读快照里的 `CurrentParsed`/`BackupParsed`。** 打开对话框后
   文件被改写时，按钮状态不会实时刷新（面板每 2 秒轮询只更新 `_btnArbitrate`，不更新
   已打开的模态对话框）。动作入口仍会按磁盘字节拒绝（§5 第 25–26 行），所以不会误写，
   但用户可能点到一个「看起来可用、点了才报变化」的按钮。这是 G16 既有设计
   （快照 + 动作时复核），本轮不改。
6. **`Ctrl+C`/Esc 关闭对话框**走 `_btnLater`（`CancelButton`），与「稍后」同语义，未单独断言。
7. **未验证 `BackupParsed` 为 true 但备份在打开后变坏的中间态**在真实 UI 上的表现
   ——`G20_BackupBecomesCorruptAfterCapture_RestoreRefusedAndFilesKept` 覆盖了动作层。
