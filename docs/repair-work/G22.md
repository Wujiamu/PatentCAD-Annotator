### 缺陷（修复前）

两套安装器的 catch 都以「是否已经移动旧目录」推断「是否存在旧安装」：

```powershell
$filesComplete = $false
if ($targetMovedToBackup) { ...恢复备份并核对... }
else {
    # No previous installation existed
    $filesComplete = -not (Test-Path -LiteralPath $installFull)
}
```

暂存复制／哈希校验或旧目录 `Move-Item` 失败时，`targetMovedToBackup` 与 `newTargetInstalled` 都是 `false`，旧目录**完整地留在原位**。此时：

1. catch 无条件清空三个注册项（`Remove-*-RegistryTree`）；
2. 走到 `else` 分支，按「原来没有安装」要求 `$installFull` 不存在；
3. 目标目录仍存在 → `$filesComplete = $false` → 不恢复注册。

结果：旧文件字节完全没变（哈希不变），但加载项已被注销、且没有任何恢复动作。文件完好而产品不可用。

## 3. 改动

### 3.1 `office-com-addin/install-office-addin.ps1`、`install-visio-addin.ps1`

**a) 在进入 `try` 之前保存旧安装状态**（两套同构）

```powershell
$hadExistingInstall = $false
if (Test-Path -LiteralPath $installFull) {
    $manifest = Assert-PatentMarkerOwnedDirectory -InstallDirectory $installFull   # Visio: [void](Assert-VisioOwnedDirectory ...)
    $hadExistingInstall = $true
}
```

该判断与 `Assert-*-OwnedDirectory` 同处，因此「存在旧安装」= 「存在**完整且哈希匹配**的旧安装」。半删除或清单不符的目录不会走到这里，行为不变。

**b) 回滚三分支，按各自状态判断**

```powershell
if ($targetMovedToBackup) { ...恢复备份、核对完整性与哈希... }   # G18，不变
elseif ($hadExistingInstall) {
    # 旧目录未动：原地核对，绝不删除
    if (Test-Path -LiteralPath $installFull -PathType Container) {
        try { [void](Assert-PatentMarkerOwnedDirectory -InstallDirectory $installFull); $filesComplete = $true }
        catch { Write-Warning "未移动的旧产品目录未通过完整性与哈希核对：$($_.Exception.Message)" }
    }
}
else { $filesComplete = -not (Test-Path -LiteralPath $installFull) }   # 首次安装，不变
```

旧目录未动时**不删除、不移动**，只做 `Assert-*-OwnedDirectory`（完整文件集＋清单＋哈希）。`$hadExistingInstall` 为假时仍是原来的「首次安装」语义。

**c) 只在本次真的写过注册项时才清空**

```powershell
$registrationTouched = $false      # 声明在 try 之前
...
$registrationTouched = $true       # 第一个 Set-*-RegistryValues 之前
...
# catch:
$registryCleared = $true
if ($registrationTouched) { foreach ($path in $registryPaths) { ...Remove-*-RegistryTree... } }
```

暂存阶段失败时注册项**从未被写过**，因此不清空。这样「完整旧安装 + 原注册项」一起保留，不需要先删再写。

**d) 未写过注册项时改为回读核对，而不是删除后重写**

```powershell
if ($filesComplete -and -not $registrationTouched) {
    $registryRestored = $true
    for (...) { Assert-*-RegistrySnapshotRestored -BaseKey $baseKey -Path $registryPaths[$index] -Snapshot $registrySnapshots[$index] }
}
elseif ($filesComplete) { ...G18 的清除→恢复→回读... }
```

仍然以**回读**为准（G18 的不变量），只是当本次没写过时回读的是「未被改动的原值」。

**e) `-FaultInjectionPoint` 扩充两值**（仅测试路径，正常安装不受影响）

| 新值 | 作用 | 失败来源 |
|---|---|---|
| `StagedCopyCorrupted` | 覆写暂存副本，让**生产**的 `复制校验失败` / `暂存校验失败` 比较抛出 | 生产哈希校验代码本身 |
| `NewMoveFails` | 用真实文件句柄占住暂存文件，使 `Move-Item $stageDirectory → $installFull` 真实失败 | Windows 重命名（`Access denied`） |

`NewMoveFails` 的句柄在 `finally` 中释放（`$script:g22StageHandle`）。

### 3.2 `office-com-addin/verify-installer.ps1`、`verify-visio-installer.ps1`

新增 G22 断言组（6 格 × 4 类断言 + 首次安装 5 项）。每项独立记 PASS/FAIL，末尾汇总失败项并抛错，**不以退出码单独判定**。

两个失败由**操作系统**制造，不是测试跳过某一步：

- **暂存目录创建失败** → 在安装父目录加 `Deny / CreateDirectories` ACE（当前用户），`New-Item` 真实被拒；`finally` 里移除 ACE。
- **旧目录 Move 失败** → 在旧产品目录内用 `[IO.File]::Open(..., FileShare::Read)` 持有真实句柄，`Move-Item` 真实被拒。

每格断言四件事：**旧文件字节**（逐文件 SHA-256）、**完整文件集 + `install-manifest.json` 逐字节**、**原注册值**（`GetSnapshotText` 全量快照比对）、**非项目哨兵**（旁边文件 + `Example.VendorAddin` 注册值）。

## 7. 排除的做法

- **把 `$filesComplete = -not (Test-Path $installFull)` 改成「目录存在即完整」**：那正是原升级缺陷的根因（半删除目录仍存在）。改为 `Assert-*-OwnedDirectory` 核对完整文件集＋清单＋哈希。
- **只加 `elseif ($hadExistingInstall)` 而不动清空逻辑**：注册项仍被无条件清空，随后 `Restore-*-RegistrySnapshot` 会把它写回来，看似可用——但那次删除/重建在「注册恢复单步失败」时会让原本完好的加载项变停用。因此同时加 `$registrationTouched` 门控：本次没写过就**不删**，只回读核对。
- **在 catch 里重算「旧目录是否完整」来判断有没有旧安装**：事后无法区分「完整旧目录」和「本次刚部署的新目录」（`AfterFiles` 后两者都完整）。必须在进入 `try` 前记录。
- **用「安装目录 mtime/存在」推断**：半删除与完整目录都可能存在，不可靠。
- **让测试直接 `throw` 模拟暂存失败**：那是跳过阶段而非制造失败。改用 ACL 拒绝与真实文件句柄，两条都是操作系统拒绝。
- **重写正常安装/卸载主流程**：未做。`try` 内除注入点外顺序不变；`uninstall-*.ps1` 完全未改。
- **为 G22 扩 `Common.psm1`**：不必要。`Assert-*-OwnedDirectory`、`Assert-*-RegistrySnapshotRestored`、`Get-*-RegistrySnapshot` 已足够，避免与 G18 的快照形状耦合再动一次。

## 8. 残余风险

1. **故障注入仍是注入**：`StagedCopyCorrupted` 由测试覆写暂存文件；`NewMoveFails` 由测试持有句柄。两者都让**生产代码**的比较/重命名真实失败（不是跳过），但真实磁盘满、杀软拦截、SMB 断连未在本机复现。
2. **ACL 拒绝依赖当前用户身份**：`Deny / CreateDirectories` 施加在临时父目录上，`finally` 移除。若运行身份是管理员且策略忽略 Deny ACE（本机不是），该格会退化为「安装成功」→ `installer_failed` 记 FAIL，不会误判为 PASS。
3. **只覆盖回滚分支**：正常安装/升级/卸载主流程未重写，也未新增更强断言；现有首次安装、重复安装、升级、卸载用例继续通过。
4. **未做真实 Office 宿主验收**：全部在隔离 `-TestRegistryRoot` + `%TEMP%` 完成，未操作真实 PowerPoint/Visio 安装目录或真实产品注册项（已核对：真实 6 个注册项与 2 个安装目录均未变）。真实宿主进程占用下的升级仍未验证。
5. **`$registrationTouched` 是新增状态**：若将来有人在第一个 `Set-*-RegistryValues` **之前**插入写注册的代码，必须同步把它设为 `$true`，否则暂存阶段失败会漏清空。当前两套都只在紧邻第一处写入前置位，位置集中易核对。
6. **BOM 易丢失**：本轮 `edit`/`write` 多次剥掉 UTF-8 BOM，已逐文件补回并纳入检查（4 个文件全部 `EF BB BF`）。后续改动必须继续核对前 3 字节，否则 Windows PowerShell 5.1 解析中文错误信息会失败。
7. **红源是重建而非原件直跑**：`red-replay-source/` 由 `red-prefix-source/` 加 try 块脚手架生成。已用 AST 比对证明 catch 体逐字节相同（6125/6121 字节），但仍属重建；若将来 `red-prefix-source/` 被改动，需重跑该比对。
8. **`upgrade_after_files_failed` 不覆盖注册写入后失败**：该格在 `AfterFiles`（文件已部署、注册未写）失败，与 `AfterRegistry`（G18 已覆盖）互补。两者之间的中间态（部分注册项已写、部分未写）未单独构造。
