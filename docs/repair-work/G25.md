同一封存记录里这四格的其余断言全部 PASS，正是「真实失败」的证据：


所以缺陷**不在**恢复核心（`DictConflict.RestoreSelectedBackup` 已正确区分 `Wrote`），也不在「写前失败」的路径，而在**对话框关闭后的视图刷新**。

### 1.1 根因（修复前源码）

**(1) 只在 `DialogResult.OK/Yes` 时刷新** — `DictPaletteControl.cs:697`（修复前）：

```csharp
DialogResult result = dlg.ShowDialog(this);
DictConflict.RecoveryOutcome outcome = dlg.Outcome;
if (result == DialogResult.OK || result == DialogResult.Yes)   // ← 唯一刷新条件
{
    if (result == DialogResult.Yes) { …ReloadAfterRecovery…; _lblStatus.Text = Strings.Conflict_RestoreOk; }
    else                            { …ReloadCurrent…;       _lblStatus.Text = Strings.Conflict_KeepWordOk; }
}
UpdateConflictState();
```

「写盘成功 + 基线失败」时 `RestoreSelectedBackup` 返回 `Succeeded=false`，`ArbitrateDialog.BtnRestoreCad_Click` 因此**不设** `DialogResult`，用户只能按「稍后」（`DialogResult.Cancel`）。两个分支都不进入 → 一次刷新都没有。

**(2) 就算刷新，也读不到变化** — `DictPaletteWorkflow.cs:20` + `:241`（修复前）：

```csharp
public bool IsFileChanged() { return DictLoader.IsFileChanged(); }
```

`IsFileChanged()` 比较的是**缓存身份**与磁盘身份。而 `DictConflict.RestoreSelectedBackup` 在 `TryWriteAtomic` 成功后立刻调用 `DictLoader.NotifySelfWrite(restored, dictPath, newIdentity)`，缓存身份**已经等于**新文件。于是：

- `IsFileChanged() == false` → 2 秒轮询永远不重载（`AutoRefreshTimer_Tick:99`）；
- `ReloadAfterRecovery` 也走 `LoadCurrent()`，返回的是 `NotifySelfWrite` 登记的那个模型。

结果：**磁盘与加载器都是 201，面板永久停在 301**。两次轮询也救不回来——这正是计划要求的「再执行两次轮询」证据。

**(3) 单次 `Outcome` 被后一次失败覆盖** — `ArbitrateDialog.cs:93`（修复前）：

```csharp
public DictConflict.RecoveryOutcome Outcome { get { return _outcome; } }
private DictConflict.RecoveryOutcome _outcome = new DictConflict.RecoveryOutcome();
```

每次点击都整体替换 `_outcome`。第一次（写盘成功、基线失败）`Wrote=true`；用户再点一次时快照已过期，`ReadSelected` 返回 `PATENTMARKER_CONTENT_CHANGED`，`Wrote=false`。**先前真实发生的写入从 `Outcome` 里消失了**，所以「是否写过盘」不能由最后一次返回值回答。

### 3.1 `RefreshArbitrationView` 的判定顺序

```csharp
private bool RefreshArbitrationView(DictConflict.RecoverySelection selection,
    DialogResult result, DictConflict.RecoveryOutcome outcome)
{
    // 1. 活动图纸已不是被裁决的那张 → 不碰视图（跨图纸保护）
    if (!DictPaletteWorkflow.IsCurrentContext(selection.Document, selection.DictPath)) return false;

    // 2. 完整成功：沿用既有加载工作流
    if (result == DialogResult.Yes || result == DialogResult.OK) { …ReloadAfterRecovery/ReloadCurrent…; return true; }

    // 3. 失败或「稍后」：按真实字节读一次当前字典
    RenameSnapshotRead read = _workflow.ReadCanonicalSnapshot(IO.RuntimeHost.ActiveDocument);
    if (read.Parsed && read.Model != null)
    {
        // 面板显示的就是这份字节时不必重载（重载会清掉该图纸的 PATCHECK 高亮）
        string shown = DictLoader.GetIdentity(_currentDict, read.DictPath);
        if (shown != null && shown == read.DictIdentity) return true;
        DictLoader.NotifySelfWrite(read.Model, read.DictPath, read.DictIdentity);
        LoadDict(read.Model);
        return true;
    }

    // 4. 规范路径不存在（图纸没有字典）→ 显示「未加载」，不继续挂旧内容
    if (!read.Read && DictPaletteWorkflow.ResolveCanonicalPath(IO.RuntimeHost.ActiveDocument) == null)
    { ShowNoDict(); return true; }

    // 5. 文件在但读不出/解析不了（含被目录顶替）→ 保留旧视图，如实报告
    return false;
}
```

第 3 步的 `GetIdentity(_currentDict, …)` **不是**「按缓存身份判断有没有变」的回归：它的语义是「缓存里仍是**这个模型对象**才返回身份」。写盘成功后 `NotifySelfWrite` 换成了**新对象**，`shown` 因此为 `null`，不会把「已写盘」误判成「未变化」。这与缺陷根因（`IsFileChanged()` 比较身份字符串）不同。

### 3.2 为什么状态栏要由对话框回答

`ArbitrateDialog` 是**唯一**知道「本次会话点了几次、每次写了没有」的地方。把会话事实放在 `DictPaletteWorkflow`（而不是 `ArbitrateDialog` 内嵌类）有两个实际原因：

1. **测试工程不编译 `ArbitrateDialog.cs`**（它需要 WinForms，`PatentMarker.Tests.csproj` 只链接 `DictPaletteWorkflow.cs`）。计划禁止改 csproj，所以纯逻辑类型放在 Workflow 里才能被 `G25_` Fact 直接断言；
2. `ArbitrateDialog` 与 `DictPaletteWorkflow` 都在计划允许改动的文件列表内，且 Workflow 已是「裁决动作」的公共门面（`IsActionAvailable` / `DescribeUnavailableActions` / `ContextGuard` 都在这里）。

`DescribeSessionStatus` 仍留在 `ArbitrateDialog`（它需要 `Strings` 与 `DialogResult`）。`Outcome` 公开面**未变**——G20 探针、G16 测试与 G05 反射依赖不受影响。

### 4.2 「再执行两次轮询」是怎么断言的

`A3` 每格在对话框关闭后调用两次 `AutoRefreshTimer_Tick`（反射调用生产轮询入口），**然后**才读 `panel`：

```csharp
f.Poll();   // ← NotifySelfWrite 已让 IsFileChanged()==false，这一拍什么都不会做
f.Poll();
Report("A3-panel-matches-disk-" + fault, panel == disk, …);
```

红版两拍之后仍 `panel=301`，绿版第一拍之前就已经是 201——这正是计划要求的「防止 `NotifySelfWrite` 让旧视图长期不动」。断言的是**面板、加载器、磁盘三者一致**：`A3-disk-*`（原始字节含期望号）、`A3-loader-*`（`DictLoader.Load` 的条目号）、`A3-panel-matches-disk-*`（`_currentDict` 的条目号）各一条。

### 4.3 跨图纸

`A5` 在模态对话框仍打开时把活动文档换成另一张图纸（其字典条目 `501`），然后按「恢复 → 稍后」关闭。断言：

- `A5-refresh-does-not-show-arbitrated-drawing-on-other`：关闭时与两次轮询后的面板都**不是** `201`；
- `A5-panel-is-unchanged-or-active-drawing`：面板要么仍是原视图 `301`，要么是活动图纸自己的 `501`；
- `A5-active-drawing-shown-after-activation`：随后正常激活路径显示 `501`；
- `A5-other-drawing-number-intact`：另一张图纸的磁盘内容仍是 `501`。

绿版实测 `panel_at_close=301|panel_after_polls=501`：关闭时不碰视图，轮询按活动图纸刷新。红版同样 PASS（红版本来就不刷新），这条是**新行为的护栏**而不是红灯。

### 8.2 残余风险

1. **`_btnArbitrate` 仍可达的语义是「磁盘上还有 `.bak`」。** 部分写入（基线失败 / 备份删除失败）之后备份确实还在，所以入口继续可点；用户再点会得到 `PATENTMARKER_CONTENT_CHANGED`（快照已过期）。这是既有设计（快照 + 动作时复核），本轮不改，但真实 UI 里用户可能看到一个「点了才报变化」的按钮。
2. **状态栏在部分写入时只有一句结论。** `裁决失败: 字典已写入，但基线更新失败；恢复点已保留。` 不再同时展示「本次尝试的 `PATENTMARKER_CONTENT_CHANGED`」。`LastError` 仍在 `SessionFact` 里（`A6-session-reports-no-full-success` 断言它非空），但没进状态栏，避免两句话互相矛盾。
3. **`GetIdentity(_currentDict, …)` 的对象引用语义**（§3.1 第 3 步）。若未来有人把 `DictWriter`/恢复核心改成不调 `NotifySelfWrite`，`shown` 会一直为 `null`，于是每次都重载——功能正确但会清掉该图纸的 PATCHECK 高亮。这是安全侧退让（视图一定对齐磁盘），不是数据隐患。
4. **`ReadCanonicalSnapshot` 与面板刷新之间仍有窗口。** 恢复写盘之后、面板读盘之前若外部又改写文件，面板会显示**外部最新内容**（这仍然「与真实当前文件一致」），但状态栏的会话结论来自恢复那一刻。这是既有的「原子替换不等于双写锁」边界，本包没有、也不声称解决并发丢更新。
5. **跨图纸时状态栏仍报裁决结论。** `A5` 里活动图纸已换成 B，`DescribeSessionStatus` 仍返回 `裁决失败: 字典已写入…`（针对 A 的裁决）。计划要求「不把原图纸模型显示到另一活动图纸」——视图已守住，状态栏文案的归属属于 L3 观感问题，本包未解决。
6. **`RefreshArbitrationView` 返回 `false` 时状态栏保留上一句。** 文件被目录顶替等极端情况下，面板不刷新、状态栏也不改写（`DescribeSessionStatus` 仍会按会话事实写入，因为它在 `using` 块内独立执行）。此时用户看到的是「裁决失败: …」而不是「字典读不出来」，属于措辞缺口。
7. **`ArbitrationSessionFact` 是内存结构，不写盘、不跨会话。** 面板重开或图纸重载后历史消失。这是有意的（计划要求「只活在对话框实例里」），但也意味着「上次裁决写了盘」不会被后续会话记住。
