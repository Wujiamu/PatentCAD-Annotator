# G15 — 主代理（R-016 补修）

基线：当前集成快照（HEAD `b945b1a6` + 前几轮已集成内容）。本轮只补 R-016，不重做 G02 原修复。

## 缺陷

原 R-016 修复只覆盖了**编号在前**的分支（`NumberStartOk(text, m.Index)`）。**名称在前**的分支没有做左边界检查，而 `G02_NAMEFIRST` 允许数字，正则回溯会把超长编号的首位让给名称：

| 输入 | 修复前 | 期望 |
|---|---|---|
| `底座123456、` | number=`23456` name=`底座1` | 不匹配 |
| `底座 123456、` | number=`23456` name=`底座 1` | 不匹配 |
| `底座S123456、` | number=`23456` name=`底座S1` | 不匹配 |

## 改动

| 文件 | 改动 |
|---|---|
| `cad-plugin/Shared/IO/MarkingTextParser.cs` | `CollectHits` 的 `nameFirst` 分支增加 `accept = NumberStartOk(text, m.Groups[2].Index)`，复用已有函数，不新增词法。 |
| `vba/Patterns.bas` | `CollectHits` 的 `nameFirst` 分支在匹配片段内用 `InStr` 定位编号起点，再调同一个 `NumberStartOk`。VBScript 没有捕获组 Index，这是两侧等价的最小做法。 |
| `tools/test-g02-parser.vbs` | 探针自带一份 `CollectHits` 副本（它验证的是引擎语义等价，不执行生产 Sub），同样补上该检查，否则探针抓不到原缺陷。 |
| `tools/G02ParserProbe/g02-cases.txt`、`g02-expected.txt` | 新增 8 个 `g15-*` 用例。零命中用 `S <id>\t0` 表达——`R <id>\t`（空条目）只填 raw 视图，`hits` 保持 -1 即**不校验条数**，那样写等于没断言。 |
| `cad-plugin/2025/PatentMarker.Tests/G15NumberBoundaryTests.cs`（新建） | 18 个 `G15_` Fact。 |

不新增总字符串长度规则，不收紧 `G02_NUM` 的 `{1,5}` 上限，不动表格预处理。

## 保留的既有行为

- `底座12345、`、`底座S12345、`、`支架10-1、`、`底座(12345)、` 仍匹配。
- `第2定位件 123、` 这类**名称自带数字**的合法输入不被连带拒绝（左边界检查看的是编号起点前一字符，不是名称内部）。
- `123456底座，`（编号在前超长）仍拒绝，原 R-016 修复不回退。
- 混排顺序 `支架2、1底座，` 仍按原文输出 `2|支架 1|底座`。

## 残余风险

- 五版真实编译已跑通；`MarkingTextParser.cs` 的改动满足 .NET 2.0／旧 C# 约束。
- `底座\t123456、` 修复前后都返回 0 命中，但原因不同（Tab 不在 `G02_NAMEFIRST` 字符类里），未单独断言 Tab 语义。
- R-021 的跨引擎等价边界不变：仍只在 ASCII 字母数字编号上实测。
