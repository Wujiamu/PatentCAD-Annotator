## R-031 先核验：宿主实测已推翻“需要套旋转公式才能修的缺陷推断”，确认缺陷成立

计划要求先收集真实属性再写算法，不许直接套旋转公式。本轮用两个只读探针在 **PowerPoint 16.0** 真实 COM 宿主上采集，字体/渲染无关：

- `tools/probe-r031-ppt-geometry.ps1`：新建未保存演示文稿，记录 `Left/Top/Width/Height/Rotation/HorizontalFlip/VerticalFlip` 与箭头样式。
- `tools/probe-r031-rotation-sign.ps1`：把“箭头端”当作可观测的端点标记（直线 180° 旋转后像素重合，只有箭头能区分首尾），导出 PNG 后按列统计笔画厚度定位箭头端。

实测结论（证据 `docs/test-evidence/repair-20261031/G11/r031-sign/probe.txt` 与同目录 PNG）：

| 场景 | 实测 | 含义 |
|---|---|---|
| `h-rot0` | Lthick=3, Rthick=9 | 箭头在右端 |
| `h-rot90` | 线段变成竖线，ink 覆盖整列 80–719 | 顺时针 90° |
| `h-rot180` | Lthick=9, Rthick=3 | 箭头移到左端，而 `Left/Top/Width/Height/Flip` **完全不变** |
| `h-rot270` | Lthick=6, Rthick=638（顶部短横带） | 箭头到顶端 |
| `rev` | `flipH=-1`，Lthick=8/Rthick=2 | 反向绘制由 Flip 编码，不是 Rotation |

即：**`Rotation` 不体现在 Left/Top/Width/Height/Flip 里**，原实现只按这四项推算端点，对任何旋转过的线都会把编号放到错误的一端。R-031 的缺陷推断成立，且修复只需要几何变换，不需要也不应该按“模型里的边框+旋转反推”硬套公式。旋转方向为顺时针（y 轴向下，标准旋转矩阵直接适用）。

## 契约差量

1. PPT 漏标扫描现在会进入嵌套组合；被用户组合过的既有标注不再报漏标。
2. 已标判定新增“可见文字 = 身份标签”条件。**用户把标签文字改掉后，该编号会被报为漏标**（这是缺陷修复的目标行为，不是回归）。
3. `GetLineEndpoints` 对 `Rotation != 0` 的线返回旋转后的端点；编号锚点位置随之改变。普通未旋转线行为不变。
4. 新增诊断阶段名 `annotation.scan`（`SKIP` 结果）。既有 `annotation.create` 未改。

## 已排除方案

- **直接对 `MxRot`/`Rotation` 套一个猜出来的公式**：计划明确禁止。改为先取宿主实测，再写与实测一致的最小变换。
- **为了扫描嵌套组合而把顶层组也当容器递归进去**：会重复计数，且会把用户组合里的普通图形当标注。改为“先判定本组合是否是产品标注，是则认领并停止下钻，否则继续下钻”。
- **改 G10 的 `PaletteForm` 显示损坏统计**：R-014 只需要可诊断，不改面板归属。

## 续接点与残余风险

### 真实 PowerPoint 16.0 宿主复核（2026-11-01）

三个只读／自建演示文稿探针（`tools/probe-g11-host-*.ps1`，均使用私有 PowerPoint 实例和新建未保存文稿，结束后关闭不写用户文件）：

| 探针 | 结论 | 证据 |
|---|---|---|
| `probe-g11-host-tags.ps1` | 用户把产品标注组与另一个矩形组合后，PowerPoint **展平内层组**：`outerItems=3`，内层组的 `PATMARKER`/`PATNUMBER` **Tags 全部丢失**，子项都是普通直线/文本框/矩形且无 Tags。真“组之组”（先组合两个普通形状再与标注组组合）同样展平为 4 个普通子项。 | `host-tags/probe.txt` |
| `probe-g11-host-roundtrip.ps1` | 未组合的标注组在保存→重开后 Tags 与识别结果保留（`3.reopened marked=301`）；复制粘贴产生的副本也保留 Tags。 | `host-roundtrip*/probe.txt` |
| `probe-g11-host-nested`／`host-r012` | 组合后的标注不再被认领（`B.marked=`、`C.marked=`），保存重开仍不认领。 | `host-r012/probe.txt` |
| 直接调用 `GetMarkedNumbers` + `TryGetVisibleLabel` | 文字改成 `999` 后 `marked=`（不再报旧号），清空后同样不报，改回 ` 301 `（带空白）后 `marked=301`。 | `host-r014/probe.txt` |

**R-012 的缺陷前提被宿主推翻。** 原清单假设“有效的产品直线＋编号组合仍保留身份 Tags，只是被放进外层组合”。真实 PowerPoint 16.0 的行为是：组合操作会把内层组展平并丢弃其 Tags，因此组合后的对象**已经不再是产品标注**，扫描不认领它是正确行为，不是漏报。递归扫描仍保留（成本低、且能覆盖未来宿主保留嵌套的情况，并有内存桩用例），但**不能**把“组合后报漏标”当作已修复的缺陷来宣称。R-012 的实际结论应改为：**在真实宿主上未复现该缺陷；原反例只在内存桩里成立，因为桩假设宿主会保留嵌套身份**。

**R-014 在真实宿主上验证通过**（改字/清空不再报旧号，带空白仍按 `NumberIdentity` 视为同号）。
