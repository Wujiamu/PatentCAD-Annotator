## 契约差量

1. 两个卸载器新增 `-FaultInjectionPoint`（`None`/`AfterPartialDelete`，默认 `None`）。真实使用不受影响。
2. 卸载失败时的输出语义：还原成功 → `已从恢复副本还原完整产品文件`；还原不可确认 → `卸载失败且未能确认完整还原。恢复副本保留于：…；卸载暂存目录：…`。**不再**存在“把残片目录改回原名即视为恢复”的路径。
3. 成功卸载路径新增清理恢复副本；`AfterPartialDelete` 注入点会在抛出前先删掉暂存目录中的一个文件，以复现“递归删除中途失败”的真实残片状态。

## 已排除方案

- **用锁定文件制造删除阶段失败**：Windows 拒绝改名含打开子文件的目录，锁定文件只会让 `Move-Item` 失败，永远到不了递归删除阶段（已用 `[IO.Directory]::Move` 与 `Remove-Item -Recurse` 双向实测确认）。因此改用注入点，而不是伪称锁定文件覆盖了该阶段。
- **把 `OfficeAddin.Common.psm1` 里的恢复函数做成通用事务库**：只加两个针对产品目录的窄函数，保持现有所有权清单与同级路径断言。
