## 契约差量（影响后继包）

1. `PatEntityHelper.RenameNumberInModelSpace` 与 `DictPaletteCadService.RenameNumber` 的返回类型从 `int` 变为结果对象。仓库内调用方已全部迁移（`DictPaletteControl`、`DictPaletteCadServiceTests`、`G06RenameResultTests`）；不再有返回“成功条数”的旧入口。
2. 一致性策略：**同一次 CAD 改号是一个事务**。任一目标写失败 → `Abort()` → 图纸保持旧号，结果报 `Changed=0`／`Committed=false`，不把曾成功的数量报成已更新。
3. JSON 与 DWG 仍不是统一事务：字典已经写入新号而图纸失败时，界面明确显示“字典已改，图纸未完成”，保留旧号／新号与失败对象，提供针对该操作的显式重试；**不**自动回写旧 JSON 做补偿。
4. 新增 `DictFileVisibility` 之外的字符串资源两处；其他包如需改文案请避免覆盖。

## 已排除方案

- **在面板里累积成功计数再显示**：这正是原缺陷形态，无法区分“没有旧号”与“匹配但写失败”。改为结果对象。
- **失败后自动回写旧 JSON“补偿”**：会覆盖期间可能更新的外部数据，计划明确禁止。
- **为改号建通用的分布式事务/两阶段提交**：超出范围；单次 CAD 事务 + 显式重试已满足关闭标准。

| `G06_AllMatchesSucceed_ReportsComplete` | 两处同号全成功 → `Changed=2`、`Complete=true`、出现 commit | PASS（对照） | PASS |

红灯说明：R-004 的原缺陷是“吞掉失败并返回成功数”，旧签名的返回类型无法表达“匹配 2 个、成功 0 个”，因此该反例在旧接口上不可能变红——不是“修复后才新增的恒绿测试”，而是旧接口缺少结果维度。为避免这一点，`G06_PartialFailure_…` 与 `G06_TransactionCommitFailure_…` 同时断言**回滚 trace**（`transaction.rollback` 存在、本次无 `transaction.commit`），这是旧实现不会有的行为；`G06_PlainTextWithSameNumber_IsNotRenamed` 与 `G06_AllMatchesSucceed_ReportsComplete` 作为对照，证明新断言没有把正常路径一起改坏。
