## 契约差量

1. **编号词法（R-016）**：新增完整词法 `[A-Z]?[0-9]{1,5}(?:-[A-Z]?[0-9]{1,5})?(?:[A-Za-z][0-9]*)?`，字母前缀／连字符子编号／字母后缀都不再被截断。**超长编号（6 位以上）显式不匹配**（`123456底座，` → 0 命中），不再静默截成尾部数字。这是有意的行为收紧：`docs/repair-backlog.md:226–233` 把「静默截短」列为数据错误，本包选择显式拒绝而非保留整串，因为 1–5 位是既有产品约定。若后续产品要求支持 6 位以上，只需放宽 `{1,5}`，不影响其它规则。
2. **原始命中通路（R-017）**：新增 `ExtractAllRaw`（C# `List<MarkingHit>`；VBA `Variant` 数组）。`ExtractAll` 保持原契约（按 `(number,name)` 去重、首次出现顺序），实现为 `Dedupe(ExtractAllRaw(text))`，因此**没有任何重复条目流入字典**。`DictModel.BuildModel` 的 `occurrences`／`nameCounts` 改从 `ExtractAllRaw` 累加。
3. **输出顺序（R-018）**：获胜命中一律按原文 `Position` **稳定插入排序**（同位置保持收集顺序，即旧的「旧格式优先」）。命中裁决不变：旧格式区间优先，与之重叠的新格式命中丢弃，裸列表命中不占区间。**因此既有测试 `MarkingTextParserTests.EndToEnd_SectionExtractThenParse` 的注释「梯队顺序（与 VBA 一致）」正是 R-018 的缺陷描述**，本包把它改为按原文顺序（`1底座、2支架、3泵体、加热器1、箱体结构10、隔板131a`）并更新注释说明。这是唯一被修改的既有断言，改动范围仅此一个方法。
4. **编号身份（R-021）**：`DictModel.BuildModel` 的 `entries` 字典设 `CompareMode = 1`（TextCompare），键为 `Trim$(number)`；条目内保存**首次命中的编号原文** `number` 用于显示，`outEntry("number")` 与 `conflicts`／`warnings` 都用该原文，不做大写化、不转整数。同号不同名进入**同一组**的 `conflicts`（每号一组，候选为原文名称）。**名称比较规则未改**（`nameCounts` 仍是默认二进制比较）。这与 `docs/repair-plan.md:141`「不能只凭本机 CompareMode 的区域设置推定与 OrdinalIgnoreCase 等价」相符：等价性由 `G02_R021_IdentityIgnoresCaseButDisplayKeepsOriginal`、`G02_R021_NumberIdentityComparerMatchesAreEqual` 和 L2 探针的 `r021|*` 选择器实测，不是推断。
5. **段落文末（R-032）**：两侧都不再使用 `\Z`。共享常量 `G02_SECTIONEND` = `[\s\S]*?(\r\n WS*\r\n|\n WS*\n|\r WS*\r|(?![\s\S]))`，C# 与 VBA 逐字相同。`(?![\s\S])` 是 `.NET \z` 与 VBScript 真文末的等价写法（两个真实引擎已验证，见证据）。标记头模式的 `\s*` 也统一改为显式 `G02_WS`。
6. **行内空白（R-033）**：裸列表 `G02_P3` 用 `G02_INLINE = "[ \t]"`，名称↔编号与行首／行尾都不跨行；`Preprocess`／`ExtractAllRaw` 仍把 `\r`→`\n`、`<br…>`→空格、Word 表格 `\r\x07` 流照旧处理，CR／LF／CRLF 多行列表仍按行匹配。
7. **共享模式文本**：`vba/Patterns.bas` 的 `Public Const G02_*` 与 `MarkingTextParser.cs` 的 `internal const string G02_*` **逐字相同**，由 `tools/test-g02-parser.vbs` 的 `pattern-text|*` 选择器直接比对（24 项）。这是一致性检查，不是语义等价证明；语义等价由同语料的逐例断言证明。
8. **VBA 局部变量改名**：`ExtractMarkingSection` 内 `Dim patterns` 改名为 `hdrPatterns`。原代码在 `patterns = Array(…)` 里内联字面量，改名后引用 `Patterns.G02_HDR*`；若保留同名局部变量会遮蔽 `Patterns` 模块名，VBA 编译失败（本轮实测卡在模态编译对话框）。**这是集成者需要知道的行为细节，不是对外契约变化。**

## 已排除方案

- **保留 `\Z` 并让 C# 改成 `\Z`**：排除。`\Z` 在 .NET 停在末尾换行之前、在 VBScript 是字面量 `Z`，两侧都不可能同时正确；用 `(?![\s\S])` 才有共同语义。
- **手抄两侧模式字符串**：排除。手抄无法证明两侧真的用同一段文本；改为 `Const`/`const` + 探针直接读文件比对。
- **让 `G02_NUMN`（字母后缀必须带数字）只用于编号在前的模式**：**已排除并回退**。曾试过让 `2Z形支架` 拆成 `2`+`Z形支架`，但 `Fixtures/vba-corpus` 的真实语料 `2442U形架` 依赖 `2442U` 作为完整编号（`CorpusComparisonTests` 报 `C#=(2442,U形架) VBA=(2442U,形架)`）。既有 VBA 语料与 `docs/repair-backlog.md:366` 自身记录都把 `2Z` 视为编号，故本包**统一使用单一词法**，R-032 只修段落边界。`2Z形支架` 的拆分保持不变（`2Z`+`形支架`），R-032 只断言「Z 之后的条目不被截断」。
- **用 `dotnet test` 作为验收入口**：排除。本机 VSTest 因无法打开父进程句柄在断言前中止，属环境 SKIP，不是产品失败；统一用 `tools/run-fact-tests.ps1`（`tools/FactRunner`）。
- **直接 `ExecuteGlobal` 复用 `.bas`**：排除。`.bas` 无法被 VBScript 直接执行（`Attribute VB_Name`／`Option Explicit` 冲突）；改为「探针从 `.bas` 解析常量文本 + 重建正则」，真实 VBA 执行走 Word 导入（L2）。
- **在 VBScript 探针里写中文**：排除。`cscript` 源文件按系统 ANSI 解码，UTF-8／UTF-16 源都会报「无效字符」；探针源保持纯 ASCII，中文用 `ChrW()` 构造，语料用 UTF-16 数据文件。
- **`New Collection` / `Count()` 同名函数 / `Set` 存对象到 `Dictionary` 值**：排除（VBScript 均不支持，实测报错）。列表用 `Scripting.Dictionary` 自建，计数函数改名 `HitCount`，期望值存字符串。

## 未完成与风险

1. **L3／L4 未做**：未用部署包安装到真实 Startup，未在安装后新进程验证自动导出链路。Word 16.0 的 L2 通过不能外推到部署包、32 位 Office 或其它 Word 版本。
2. **五版编译未做**：`Shared/IO/MarkingTextParser.cs` 的改动只经 2025 测试工程编译（`net8.0-windows`）。该文件与 `NumberIdentity.cs` 同时被 2007/2010/2013/2015 链接，须满足 .NET 2.0／旧 C# 约束；本包**刻意未引入 LINQ、未使用新版 BCL API**（只用了 `Regex`、`List<T>`、`StringBuilder`、`string`，`NumberIdentity` 未改），但仍需五版真实编译确认。
3. **`NumberIdentity` 与 VBA TextCompare 的等价性边界**：只在 **ASCII 字母数字编号**上实测等价（`G02_R021_*` 与 L2 `r021|*`）。`NumberIdentity` 用 `OrdinalIgnoreCase` + `Trim()`（`Trim` 去所有 Unicode 空白），VBA 侧用 `Trim$`（只去空格）+ `CompareMode=1`（受本机区域设置影响）。**非 ASCII 编号或首尾为 Tab／全角空格时两侧可能不同**。`docs/repair-plan.md:141` 明确要求「范围限支持的 ASCII 字母数字编号」，本包据此声明范围，未做全 Unicode 等价。
4. **VBScript `CompareMode` 依赖区域设置**：`Scripting.Dictionary` 的 TextCompare 使用本机区域（当前系统区域为中文）。在其它区域设置下大小写折叠规则可能不同；这一点未在其它区域实测，与 `NumberIdentity` 的 `OrdinalIgnoreCase`（不受区域影响）存在理论偏差。
5. **`123456底座，` 由「截成 12345」改为「0 命中」**：这是可见行为变化。若现场文档真存在 6 位以上编号，这些标注会从字典消失而不是变成错误编号。`docs/repair-backlog.md:226–233` 倾向「显式拒绝或整串保留」，本包选前者；若产品要求改为整串保留，只需放宽词法位数上限。
6. **`2Z形支架` 仍拆为 `2Z`+`形支架`**：与既有 VBA 语料（`2442U形架`）一致，本包未改变。若产品希望拆成 `2`+`Z形支架`，需要同时更新语料基线与 `CorpusComparisonTests`，属另一项契约决定。
7. **语料基线未更新**：`Fixtures/vba-corpus/vba-expected-v4-output.txt` 与 `parser-contract.json` 哈希与基线一致，全套 196 PASS 说明现有 8 例语料在当前实现下仍成立。本包**未**运行 `tools/generate-vba-corpus.vbs`（会改写目标目录的预期文件），也未用实现输出覆盖期望。
8. **`ExtractAllRaw` 是新增公开入口**：VBA 侧 `Public Function ExtractAllRaw`、C# 侧 `public static List<MarkingHit> ExtractAllRaw`。`AGENTS.md` §4 对 Word 公开 Sub 的限制针对用户命令入口（`ShowPatentDictPanel`／`AutoExec`／`AutoExit`）；`ExtractAllRaw` 是模块内解析函数，与既有 `Public Function ExtractAll` 同级，不构成新增用户命令。集成时若门禁要求核对公开入口清单，请确认这一点。
