### 1.1 三组缺陷的根因（修复前源码）

**(1) 提交快照在对话框关闭并 Reload 之后重建** — `DictPaletteControl.cs:836-851`：

```csharp
var dict = _workflow.LoadCurrent();        // ← 先 Reload
if (dict != null) LoadDict(dict);
...
string writtenIdentity = DictLoader.GetIdentity(_currentDict, dictPath);   // ← 从"新加载的模型"取身份
RenameSyncContext context = RenameSyncContext.Capture(document, dictPath, writtenIdentity);
```

`GetIdentity` 只在缓存里仍是**同一个模型对象**时才返回身份。Reload 之后 `_currentDict` 已经是新对象：若文件在这窗口里被外部合法 JSON 替换，返回的就是**外部那一版的身份**；若文件被删除，`GetIdentity` 返回 `null` → `Capture` 回读磁盘 → `MISSING`。两种都被当成「本次提交版本」，于是首次同步照常调 CAD 且不留欠账。

**(2) 重试/重新确认用缓存模型和缓存路径** — `DictPaletteControl.cs:1022-1026`、`:1059`：

```csharp
RenameSyncContext context = RenameSyncContext.Capture(
    IO.RuntimeHost.ActiveDocument, _workflow.ResolveDictPath());   // ← ResolveDictPath 优先返回仍存在的缓存路径
DictModel model = _currentDict;                                   // ← 面板缓存里的旧模型
RenameRetryPlanner.Decide(pending, context, delegate (string n) { return _workflow.FindEntry(model, n); });
```

`ResolveDictPath()` 的注释自己写着「A cached path can outlive a deleted/renamed dictionary」，但它在文件仍存在时就返回缓存路径；`_currentDict` 在热刷新后可能落后于磁盘、在损坏文件上可能仍是上一版合法模型。于是「当前字典已经没有新号」「当前文件已经损坏」都被判成「还有新号」，CAD 被无谓调用。

**(3) 按钮、确认阶段、释放都是全局的**

```csharp
private bool _pendingRenameAwaitingReconfirm;                    // ← 一个面板一个确认位
private void ShowRenameRetry(bool visible) { …Visible = visible; }  // ← 一个面板一个可见性
public void ReleaseForDrawing(string drawingPath, object document) {
    if (document != null) _byDocument.Remove(document);   // ← 删掉该对象
    …按 drawingPath 遍历删除…                              // ← 然后仍然按历史路径再删一遍
}
```

所以 B 自己有欠账却看不到按钮、B 没有欠账却显示按钮、A 的确认阶段被 B 的第一次点击消费，以及 A 另存为之后关闭一张在 A **旧路径**上重开的 B 会顺带删掉 A 的欠账。

## 3. 三部分的最小改法

### 3.1 提交快照由写入方保存

`EditEntryDialog.ApplyAndWrite()` 里 `WriteBack()` 返回 true 的**那一刻**：

```csharp
_commit.Written = true;
_commit.Document = _document;                                  // 打开对话框时的目标图纸
_commit.DrawingPath = RenameSyncContext.DrawingPathOf(_document);
_commit.DictPath = RenameSyncContext.FullPath(_dictPath);
_commit.DictIdentity = DictLoader.GetIdentity(_model, _dictPath);   // NotifySelfWrite 登记的那一份
```

`GetIdentity` 的语义恰好是「缓存里仍是**这个模型对象**才返回身份」，所以拿到的就是 `DictWriter` 真正序列化出的字节身份，而不是之后回读的结果。`EditSelectedEntry` 改成：

```csharp
commit = dlg.CommitFact.Copy();          // ← 在 using 块里、Reload 之前
if (r == DialogResult.OK || r == DialogResult.Abort) { …LoadCurrent(); LoadDict(…);… }
if (r == DialogResult.OK && commit != null && commit.NumberChanged)
    RenameLeadersInDrawing(commit.OldNumber, commit.NewNumber, commit);
```

三条硬规则：

1. **空身份不退化。** `RenameCommitFact.HasTrustedIdentity` 要求 `Written && Document != null && DictPath 非空 && DictIdentity 非空且不是 MISSING`。`ToContext()` 在不可信时返回 `null`，调用方**不会**走 `RenameSyncContext.Capture(...)` 去回读当前文件。
2. **MISSING 不是成功提交。** 被删除的文件得到 `MissingIdentity`，`DescribeUntrusted()` 返回「本次编辑写出的字典已无法识别（被替换或删除），请重载字典后重新确认」，登记欠账 + 要求重新确认 + 保留放弃入口，**CAD 零调用**。
3. **编号/名称语义与回滚不变。** `NumberChanged` 额外要求 `OldNumber` 非空：新增条目（`_entry == null`）不触发同步；名称编辑仍然不碰图纸；`WriteBack()` 失败的 `RestoreModelMutation` 路径完全没动。

### 3.2 首次同步与重试都核对规范路径和真实内容

`DictPaletteWorkflow` 新增两个读法，都是**同一套约定**：

```csharp
public static string ResolveCanonicalPath(object document)   // 活动文档引用相等 + DictLoader.ResolveDictPath() + GetFullPath
public RenameSnapshotRead ReadSnapshot(string dictPath)      // 一次 ReadAllBytes → 身份；同一份 bytes → DictLoader.Load
public RenameSnapshotRead ReadCanonicalSnapshot(object document)
```

`ReadSnapshot` 刻意**绕过** `DictLoader` 的按路径缓存：身份和模型都来自同一次 `File.ReadAllBytes`，两者必然对应同一份内容；热刷新后的旧模型、损坏文件上残留的旧模型都不会被借来判定。`RenameSnapshotRead` 明确区分三种状态：读取失败（`Read=false`）、读到但解析失败（`Parsed=false`）、成功（`Parsed=true` + `Model`）。

判定函数是 `RenameRetryPlanner.DecideOnBytes(pending, context, snapshot)`，判定顺序与既有 `Decide` 完全一致（`NoPending` → `WrongDocument` → `NeedsReconfirm` → `MissingNumber` → `Ready`），只把第 4 步的输入换成真实字节解析出的模型：

| 实际状态 | 结果 | 行为 |
|---|---|---|
| 文档不是同一张 | `WrongDocument` | 不写图 |
| 读不出真实字节（损坏/被删/被目录顶替） | `NeedsReconfirm` + `SnapshotUnreadable` | 保留任务、CAD 零调用 |
| 字节与记录不一致 | `NeedsReconfirm` | 保留任务、CAD 零调用 |
| 字节一致但解析失败 | `NeedsReconfirm` + `SnapshotUnparsable` | 保留任务、CAD 零调用 |
| 字节一致、解析成功、无新号 | `MissingNumber` | 保留任务、CAD 零调用 |
| 字节一致、解析成功、含新号 | `Ready` | 调用 CAD |

`ConfirmPendingRenameRetry` 现在**先读字节再换绑**：读取失败 → 不换绑；解析失败 → 不换绑；没有新号 → 不换绑。只有「读到 + 解析出 + 含新号」才 `Rebind` 到 `snapshot.DictIdentity`。**绝不**用 `_currentDict` 配新身份。

首次同步侧：`RenameLeadersInDrawing` 先判 `commit.HasTrustedIdentity`，再判 `context.DescribeContextDrift()`——后者在 `DescribeDrift`（文档 + 字节）之外增加 `DictPaletteWorkflow.IsCurrentContext(Document, DictPath)`，因此目录里仍残留的旧路径、另存为后的新路径、默认路径切换都被识别。`ResolveDictPath()` 的缓存路径不再参与判定。

### 3.3 入口、确认阶段、释放按 Document 归属

| 位置 | 修复前 | 修复后 |
|---|---|---|
| 重试/放弃可见性 | `ShowRenameRetry(bool)` 全局布尔 | `RefreshRenameRetryEntry()` → `ShowRenameRetryFor(ActiveDocument)`：有欠账就显示（即使 JSON 已损坏），没有就隐藏 |
| 确认阶段 | `_pendingRenameAwaitingReconfirm` 面板全局 | `PendingRenameOperation.NeedsReconfirm` 记录级；`PendingRenameRegistry.NeedsReconfirm(document)` 按图纸读 |

| 释放 | 删该对象 **然后** 仍按历史路径遍历删 | 有 Document → **只**删该对象；无 Document → 历史路径回退（兼容旧调用方） |

## 9. SKIP / BLOCKED 与残余风险

### 9.1 真实宿主（SKIP/BLOCKED，未执行）

| 项 | 原因 |
|---|---|
| 真实 AutoCAD 面板按钮操作、`DocumentActivated`/`DocumentToBeDestroyed` 真实事件注册、`DocumentLock`/`Transaction`、重启持久化 | 本机无对应宿主会话；探针只用桩 Document 与桩 CAD 服务。**L3/L4 未覆盖** |
| 2007/2010/2013/2015 真实宿主验收 | 按 AGENTS.md §1 固定范围，**GitHub 外部宿主验收**，不是本机待办 |

### 9.2 环境障碍（不是产品失败）

- **`build.ps1 -Simulation` 的 VSTest 承载被 ACL 拒绝**：testhost 启动阶段 `System.ComponentModel.Win32Exception (5): 拒绝访问`（`simulation-vstest-acl-blocked.txt`）。这是前几轮已记录的同一环境障碍（G23 §"本次主机 G16 testhost 的访问拒绝是另一环境障碍"），不是本包引入的。**改用 FactRunner 跑同一批四个工程**，得到 83/96/96/96 / 0 FAIL（`green-simulation-factrunner.txt`）——这是同一个测试程序集、同一批 Fact，只是承载器不同。报告不把它记成 VSTest PASS。

### 9.3 残余风险

1. **`EditSelectedEntry` 之后用户立刻切图纸**：`commit.Document` 是对话框打开时的引用，`DescribeContextDrift` 会判 `DocumentChanged` 并保留欠账。但「欠账落在 A 上、用户在 B 上看到状态行提示」属于 L3 观感问题，本包只保证记录不丢、CAD 不被误调。
2. **同一图纸连续两次编辑**：G21 的单槽位语义不变——第二次改号在写 JSON 之前被拦。`CommitFact` 每次成功写入都会覆盖，不存在「两次提交混用身份」。
3. **`ReadSnapshot` 与随后 CAD 事务之间仍有窗口**：`DescribeContextDrift` 在调用 CAD 前再核一次字节，但两次读取之间的外部改写仍可能发生。这是既有的「原子替换不等于双写锁」边界，本包没有、也不声称解决并发丢更新。
4. **`CommitFact.DictIdentity` 依赖 `DictLoader.GetIdentity` 的对象引用语义**：若未来有人把 `DictWriter.Write` 改成不调 `NotifySelfWrite`，或让 `GetIdentity` 不再要求对象引用相等，提交事实会静默变空。此时 `HasTrustedIdentity == false` 会**拒绝同步并保留欠账**（安全侧失败），但同步会停止工作。这是有意的失败方向，不是新增隐患。
5. **`PendingRenameOperation.NeedsReconfirm` 的跨版本兼容**：它是内存结构，不写盘，旧会话不存在。若未来要持久化欠账，需要重新设计确认位的生命周期。
6. **`ReleaseForDrawing` 的无 Document 回退仍按路径匹配**：这是为兼容只传路径的旧调用方保留的；生产调用方 `PatPaletteCommand` 两个参数都传。若未来新增只传路径的调用方，需先评估跨 Document 误删风险。
