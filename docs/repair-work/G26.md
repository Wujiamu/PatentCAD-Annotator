### 缺陷（修复前）

两套安装器的 catch 以 `$registrationTouched` 同时决定「要不要清空注册」与「能不能只回读」：

```powershell
$registryCleared = $true
if ($registrationTouched) { foreach ($path in $registryPaths) { Remove-*RegistryTree ... } }
...
if ($filesComplete -and -not $registrationTouched) {   # 只回读
elseif ($filesComplete) {                               # 清空后按快照恢复
```

"本次没写过注册值"被当成"注册项指向的文件没变"。实际有四件互不蕴含的事：

1. 原安装完整**且未移动**；
2. 产品文件路径已变（旧目录移走，或新目录已部署）；
3. 本次**写过**注册值；
4. 回滚**停用过**注册。

`targetMovedToBackup=true`、`newTargetInstalled=true` 而 `registrationTouched=false` 时，第 2 件已成立、第 1 件已不成立，代码却因为第 3 件为假而既不清空、也不恢复，最后走 `else` 分支打印「加载项保持停用」。结果：两个 L1 注册边界仍启用，`CodeBase` 指向已被移走的目录，日志与真实状态相反。

## 3. 改动

### 3.1 `office-com-addin/install-office-addin.ps1`、`install-visio-addin.ps1`（两套同构）

**a) 进入 catch 时先算出四态，再决定注册项去留**

```powershell
$pathsChanged = $targetMovedToBackup -or $newTargetInstalled        # Visio: $oldMoved -or $newInstalled
$registrationUnchanged = $true
for ($index = 0; $index -lt $registryPaths.Count; $index++) {
    if (-not $registrationUnchanged) { break }
    try { Assert-*RegistrySnapshotRestored -BaseKey $baseKey -Path $registryPaths[$index] -Snapshot $registrySnapshots[$index] }
    catch { $registrationUnchanged = $false }
}
$registrationTrusted = (-not $pathsChanged) -and (-not $registrationTouched) -and $registrationUnchanged
$registrationDisabled = $false
$registryCleared = $true
if (-not $registrationTrusted) {
    foreach ($path in $registryPaths) {
        try { Remove-*RegistryTree -BaseKey $baseKey -Path $path; $registrationDisabled = $true }
        catch { $registryCleared = $false; Write-Warning "回滚注册表项失败：$path" }
    }
}
```

`$registrationTrusted` 是"可以只回读"的唯一条件：**路径没变 且 本次没写 且 注册值仍等于安装前快照**。第三方在本次安装期间改过产品注册值时，快照比对会把它判为不可信，走清空→按快照恢复，而不是把它当成未动。

**b) 文件没被确认完整时，注册项一律停用（新增 3b 段）**

```powershell
if (-not $filesComplete -and -not $registrationDisabled) {
    foreach ($path in $registryPaths) {
        try { Remove-*RegistryTree -BaseKey $baseKey -Path $path; $registrationDisabled = $true }
        catch { Write-Warning "回滚注册表项失败：$path" }
    }
}
```

3b 只处理"未移动的旧目录自己没通过校验"这一类剩余情况，保证下面的日志不会与真实注册状态相反。

**c) 只回读 vs 按快照写回的分界改成状态而非单一 flag**

```powershell
if ($filesComplete -and $registrationTrusted -and -not $registrationDisabled) {  # 只回读
elseif ($filesComplete) {                                                        # Remove 后 Restore + 回读
```

被本轮回滚清过的注册项**不再**落入"只回读"分支（这条路径原本只由 `-not $registrationTouched` 决定）。

**d) 日志所述状态取自真实注册项**

```powershell
$registrationPresent = $false
foreach ($path in $registryPaths) { $probe = $baseKey.OpenSubKey($path); if ($probe) { $probe.Dispose(); $registrationPresent = $true } }
```

末尾告警按「文件是否完整」×「注册项是否真的存在」分支，共四类，不再无条件打印「加载项保持停用」：

| 文件 | 注册项 | 告警 |
|---|---|---|
| 完整 | 有 | `安装未完成，已恢复旧版产品文件与原注册项` |
| 完整 | 无（安装前也没有） | `安装未完成，已恢复旧版产品文件（安装前没有产品注册项）` |
| 完整 | 无 | `…原注册项未能恢复（加载项保持停用）` |
| 完整 | 有但不等于快照 | `…产品注册项与原注册项不一致，需人工确认加载项` |
| 不完整 | 无 | `…未能确认旧版完整还原，加载项保持停用` |
| 不完整 | 有 | `…但产品注册项仍然存在，需人工确认加载项` |
| 首次安装、未留下文件 | 无 | `安装未完成，未部署产品文件（安装前没有旧版安装）` |

**e) `-FaultInjectionPoint` 扩充（仅测试路径，正常安装不受影响）**

| 新值 | 作用 | 失败来源 |
|---|---|---|
| `StageVerifyBlocked` | 暂存阶段失败，同时独占占用旧产品文件 | 生产 `Assert-*OwnedDirectory` 读不到文件 → `filesComplete=false` |
| `OldMovedRestoreBlocked` | 旧目录已移入备份后失败，并占用备份内文件 | 生产 `Move-Item` 被 Windows 拒绝 |
| `NewMoveFailsOldRestoreBlocked` | 新目录 Move 失败（原有真实句柄）＋ 旧目录恢复也失败 | 两处 `Move-Item` 都被拒绝 |
| `AfterFilesOldRestoreBlocked` | 新文件已部署后失败 ＋ 旧目录恢复也失败 | 同上 |
| `AfterFilesResidueBlocked` | 新目录已部署后失败，且残片无法隔离 | `Move-Item`／递归删除都被拒绝 |
| `AfterFilesRegistrationDiverged` | 文件已部署、本次尚未写注册，第三方改掉一个产品值 | 生产快照比对发现不一致 |
| `AfterRegistryOldRestoreBlocked` | 注册已写后失败 ＋ 旧目录恢复也失败 | 生产 `Move-Item` 被拒绝 |

所有新值仍把**生产代码的比较/重命名/校验**打失败，不是跳过阶段；`NewMoveFails` 由 `-eq` 改为 `-in`，语义不变。新增句柄在 `finally` 释放（`$script:g26RestoreHandle`、`$script:g26ResidueHandle`）。

### 3.2 `office-com-addin/verify-installer.ps1`、`verify-visio-installer.ps1`

新增 G26 断言组（两套各 11 格），跑在**真实隔离 HKCU 测试根 + 临时安装树**上，每格独立记 PASS/FAIL，末尾汇总失败项并抛错，**不以退出码单独判定**。

每格断言：

1. `installer_failed` / `failure_origin` — 注入的失败确实发生且来自预期阶段；
2. `target_integrity` — 产品目录要么是与基线**逐字节**一致的完整旧集合（文件集＋哈希＋`install-manifest.json`），要么明确不是完整安装；
3. `registration_state` / `registration_absent` — 注册项存在性与预期一致，停用时**没有任何产品键**；
4. `registration_usable` — 启用的注册项 `InprocServer32\CodeBase` 必须解析到真实存在的文件且 `LoadBehavior=3`（"键在"不等于"可用"）；
5. `registration_matches_baseline` — 恢复后的注册值与安装前快照逐值相同；
6. `rollback_material` — 只有回滚未能同时确认两半时才保留 `.rollback-*`，且该副本仍是完整旧文件集；
7. `sentinel` — 非项目文件与非项目注册值零变化；
8. `log_matches_state` — 告警所述注册状态与真实注册状态一致。

## 7. 排除的做法

- **只把 `if ($registrationTouched)` 改成 `if ($registrationTouched -or $pathsChanged)`**：能修掉四个反例，但把"路径变了、旧目录又成功移回"的格也变成"先删再写"，一旦写回失败就把原本完好的加载项变成停用。改成"未移动且未写且快照仍相同才回读"，恢复成功时仍走快照写回，失败时停在停用。
- **保留 `$registrationTouched` 作为唯一判据、只在 `-not $filesComplete` 时补一次停用**：修不掉"第三方在本次安装期间改过产品注册值"。这条路径下 `registrationTouched=false`，旧代码只回读、回读失败后既不停用也不恢复，键还在但值是别人的。因此增加 `registrationUnchanged`（快照逐值比对）。
- **把 `$filesComplete = -not (Test-Path $installFull)` 改成"目录存在即完整"**：G18 的根因，未回退。
- **在 catch 里重新推断"旧目录是否完整"来判断有没有旧安装**：事后无法区分"完整旧目录"和"本次刚部署的新目录"（`AfterFiles` 之后两者都完整），继续沿用进入 try 前记录的 `$hadExistingInstall`。
- **用退出码或"键存在"判定通过**：G26 每格都断言"注册实际可用性"（`CodeBase` 指向真实文件、`LoadBehavior=3`）、目标字节完整性、恢复副本、哨兵、日志一致性；停用格要求**三个产品键一个不剩**。
- **用测试直接 `throw` 模拟恢复失败**：那是跳过阶段。`OldMovedRestoreBlocked` 等值都在备份目录里持有真实文件句柄，让生产 `Move-Item` 被 Windows 拒绝；`StageVerifyBlocked` 独占占用旧产品文件，让生产 `Assert-*OwnedDirectory` 自己失败。
- **重写正常安装/卸载主流程**：未做。try 内除注入点外顺序不变；`uninstall-*.ps1` 完全未改；Common 模块未改。
- **复用评审轮的 L1 内存矩阵作为放行证据**：计划明确「当前内存注册红灯不能替代修复后的完整隔离安装红绿」。本包全部结论来自真实 `-TestRegistryRoot` 隔离路径；评审轮的 `installer-matrix.ps1` 用 `$baseKey=$null` 等桩模拟注册表，不模拟本包新增的 `OpenSubKey` 探测与快照比对，因此不作为本包的证据入口。

## 8. 残余风险

1. **故障注入仍是注入**：旧目录恢复失败由"备份目录内有打开的子文件"制造，`AfterFilesResidueBlocked` 由"新目录内有打开的子文件"制造——都是真实的 Windows 重命名/删除拒绝，不是跳过调用；但磁盘满、杀软隔离、SMB 断连等真实环境失败未在本机复现。
2. **ACL 依赖当前用户身份**：`stage_restore_ok` 用 `Deny / CreateDirectories` 施加在临时父目录上，`finally` 移除。若运行身份是管理员且策略忽略 Deny ACE（本机不是），该格会退化成"安装成功"→ `installer_failed` 记 FAIL，不会误判为 PASS。
3. **"文件不完整且注册项仍在"的告警需要人读**：新分支 `…但产品注册项仍然存在，需人工确认加载项` 只在 `Remove-*RegistryTree` 自己抛错（如注册表被锁）时出现。矩阵未构造该格（需要注册表 ACL 拒绝，超出本包范围），只能保证措辞不再与状态相反。
4. **`stage_restore_fails` 会停用原本完好的注册项**：旧目录只是**暂时**读不到（本包用独占句柄制造）。这是"无法确认完整 → 不停用即冒险"的保守选择，代价是用户需要重跑安装；`registration_usable` 与 `log_matches_state` 都按这个语义断言。
5. **`$registrationTrusted` 的快照比对依赖 `Assert-*RegistrySnapshotRestored`**：该方法只比对值集合与值，不比对键的安全描述符；恢复后 SD 可能与该键原本的 ACL 不同（`Remove` + `CreateSubKey` 重建）。本包只在"路径已变或注册已写"时清空，未扩大清空范围，但该差异未在本轮验证。
6. **`registrationUnchanged` 会漏掉"等值改写"**：若第三方把产品值改成与安装前完全相同的内容，比对无法区分。这种情况下恢复出的注册值仍等于快照，业务结果无差别。
7. **`-StageVerifyBlocked` 等新值只是测试面**：若将来有人在第一个 `Set-*RegistryValues` 之前插入写注册的代码，必须同步维护 `$registrationTouched` / 快照比对，否则 3b 与快照比对会漏判。当前两套都只在紧邻第一处写入前置位，位置集中易核对。
8. **BOM 易丢失**：本轮 `edit` 多次剥掉 UTF-8 BOM，已逐文件补回并纳入检查（4 个文件全部 `EF BB BF`，`bareLF=0`）。后续改动必须继续核对前 3 字节，否则 Windows PowerShell 5.1 解析中文错误信息会失败并连带语法错误。
9. **未做真实宿主验收**：全部在隔离 `-TestRegistryRoot` + `%TEMP%` 完成，未操作真实 PowerPoint/Visio 安装目录或真实产品注册项，未在 Office 进程占用下升级。真实宿主进程占用下的升级与回滚仍需目标环境验证。
