## 本包改动

### 缺陷（修复前）

两套卸载 catch 均按 `registry.remove → registry.restore → files.restore` 执行，文件恢复失败时注册项仍是 Enabled=True，指向残缺目录；升级 catch 先恢复注册项，且以“原安装路径还存在”为条件跳过旧目录恢复——新目录半删除时该条件为 false，旧完整目录永远不回来。

### 修复（目标顺序逐段落地）

| 步骤 | 卸载器 | 安装器（升级） |
|---|---|---|
| 1 判断目标是否已完整 | `Assert-*OwnedDirectory`（完整文件集+哈希）通过则不再删除 | 新目录先隔离到 `.<leaf>.failed-<guid>` |
| 2 必要时从恢复副本恢复 | `Restore-*DirectoryFromCopy` | 隔离后移回 `.<leaf>.rollback-<guid>` 旧目录 |
| 3 核对完整产品集合／哈希 | 恢复后**再次** `Assert-*OwnedDirectory` | 移回后 `Assert-*OwnedDirectory` |
| 4 只有文件完整才恢复注册项并核对 | `Restore-*RegistrySnapshot` + `Assert-*RegistrySnapshotRestored` 回读 | 同左 |
| 5 最后清理恢复材料 | 仅当文件与注册都已确认才删副本/暂存 | 仅当两者都确认才删隔离/备份目录 |

关键不变量：**文件不完整时绝不恢复注册项**；注册恢复失败或清理失败都保持停用并保留材料；注册恢复以回读核对为准，不以函数“没抛异常”为准。

## 契约差量

1. 两个卸载器与两个安装器的 `-FaultInjectionPoint` 取值集合扩大。默认 `None`，真实使用路径不变（已用无注入的隔离安装+卸载复跑确认退出 0、目录清零、无残留兄弟目录）。
2. 卸载失败告警文案分三种可区分状态：
   - 文件+注册都还原 → `…已从恢复副本还原完整产品文件并恢复原注册项…`
   - 文件还原但注册未恢复 → `卸载失败：产品文件已还原，但原注册项未能恢复（加载项保持停用）…`
   - 都未确认 → `卸载失败且未能确认完整还原，加载项保持停用…`
   安装器对应 `安装未完成，已恢复旧版产品文件与原注册项` / `安装失败：旧版产品文件已还原，但原注册项未能恢复` / `安装失败且未能确认旧版完整还原`。
3. 恢复材料（`.recovery-*`、`.uninstall-*`、`.rollback-*`、`.failed-*`）只在“文件完整且注册已确认”时清理。未确认的回滚会**保留**材料并在告警里给出精确路径。
4. 内部函数 `Test-PatentMarkerRegistryValueEqual` / `Test-VisioRegistryValueEqual` 未导出，不影响其他包。

无接口变化影响 G15/G16/G17：本包只动 `office-com-addin/`，与 CAD Shared 无交集。

## 已排除方案

- **用“目录存在”判断文件是否完整**：这正是原升级缺陷的根因（新目录半删除时路径仍存在）。改为用所有权清单核对完整文件集与哈希。
- **让恢复函数返回 `$true` 就当成功**：`Restore-*DirectoryFromCopy` 的返回值只表示它自己认为复制完成；注册恢复前再跑一次 `Assert-*OwnedDirectory` 才是证据。同理注册恢复用回读断言而非“没抛异常”。
- **为 `RollbackRemovalBlocked` 写“跳过隔离”的分支来模拟**：第一次尝试这样做时，G18(f) 在修复后仍为 FAIL——因为跳过并不等于“移除失败”，残片随后被正常删除。改为真实持有文件句柄，使隔离和删除都真的失败，才复现原分支。
- **把恢复逻辑抽成通用事务库**：沿用 G14 的取舍，只保留产品目录专用的窄函数。
- **重写正常安装/卸载主流程**：未做。try 块内除注入点外保持原顺序。

## 残余风险

1. **只覆盖回滚分支**：正常安装/卸载主流程未重写，也未新增对正常路径的更强断言（现有首次安装/重复安装/升级/卸载用例继续通过）。
2. **故障注入仍是注入**：`PartialDeleteThenRestoreFails`、`RegistryRestoreFails`、`CleanupFails` 在 catch 内以条件分支模拟阶段失败；`RollbackRemovalBlocked` 用真实文件句柄。真实 ACL/磁盘满/杀软拦截未在本机复现。
3. **注册恢复回读断言依赖快照形状**：新增的 `Assert-*-RegistrySnapshotRestored` 逐值比较；若将来快照新增编码类型，需同步扩展 `Test-*-RegistryValueEqual`。
4. **未做真实 Office 宿主验收**：全部在隔离 `TestRegistryRoot` + `%TEMP%` 目录完成，未操作真实用户注册项或真实 Office 安装目录；真实 PowerPoint/Visio 进程占用下的卸载仍未验证（与 G14 相同缺口）。
5. **BOM 易丢失**：本轮编辑过程中 `edit`/`write` 多次剥掉 UTF-8 BOM，已逐文件补回并纳入检查。后续改动必须继续核对前 3 字节为 `EF BB BF`，否则 Windows PowerShell 5.1 会解析失败。
6. **材料保留会占用磁盘**：未确认的回滚会同时留下 `.recovery-*`、`.uninstall-*`/`.rollback-*`、`.failed-*`，需人工清理；产品目录仅 3 个文件，未做空间预检。
