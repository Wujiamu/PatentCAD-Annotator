# G08 — 实现 Agent（R-007）

基线：共同工作树快照 `docs/test-evidence/repair-20261031/baseline-manifest.json`；源码起点为 `b945b1a68fec26ada268b5a4ee3ac066386e96ab` 加开工时用户未提交／未跟踪文件。本包只改 `word-addin/install-vba.vbs`、`tools/verify-vba-installer.ps1`，新增 `tools/test-g08-rollback.ps1`。

## 本包改动

相对基线（冻结副本 `docs/test-evidence/repair-20261031/G08/baseline-install-vba.vbs`，SHA-256 `78CC1B5D6B7BF01C00A09AC77B2B22D413C404670F78B69224523266F66CC9A8`）的差量：

1. **清单先暂存后激活。** 新清单写到本次唯一的 `PatentMarker.addin.install.txt.pm-new-<stamp>`，关闭后 `ReadAll` 回读并与预期文本逐字符比较，通过后才 `MoveFile` 到产品路径；激活后再回读一次。原来直接 `OpenTextFile(manifestPath, ForWriting, True)` 写产品路径的路径已删除。
2. **归属记录。** `backupMade`／`manifestBackupMade`／`addinActivated`／`manifestActivated` 记录本次创建物；`RemoveOwnFile` 只删这些归属内的路径，并核对确实已删除。未知文件一律不动。
3. **恢复前先留独立参照副本。** 旧 dotm／旧清单在**任何改名之前**复制成 `.pm-old-<stamp>` 并逐字节核对，恢复后用该副本比对字节与 ReadOnly／Hidden／System 位。这解决了原实现“旧文件一旦移走就没有可信基准可比”的问题，也避免恢复时再复制出第二份同名归属物。
4. **每步保存错误并核对。** `RestoreAddin`／`RestoreManifest` 各自保存 `Err.Number`／`Err.Description`，移动后核对实际字节与属性；失败时输出 `ROLLBACK_INCOMPLETE` 与 `recovery=<路径>`，**不再**输出 `previous add-in restored`。首次安装失败单独输出 `first installation rolled back; no previous add-in existed`。
5. **新增 `/InjectFault:<stage>` 与 `/InjectFault2:<stage>` 测试缝**（仅测试用，只能增加失败、不能跳过步骤）：`addin-activate`、`manifest-write`、`manifest-close`、`manifest-content`、`manifest-activate`、`addin-restore`、`manifest-restore`、`addin-restore-corrupt`、`manifest-restore-corrupt`。后四者用真实文件系统障碍（在目标路径建目录／写入错字节）制造，而不是靠 `Err.Raise` 跳过被测代码。

不变量保持：不打开／编辑／保存／替换／删除 `Normal.dotm`，不访问 `VBProject`／`VBComponents`／`NormalTemplate`，不要求 `AccessVBOM`，只操作 `Application.StartupPath` 下的产品专属文件。`build.ps1 -Static` 的 Word 安全契约 12 项 token 全部保留（含 `If backupMade Then fso.MoveFile backupPath, targetPath`）。

## 契约差量

- 新增启动参数 `/InjectFault:`、`/InjectFault2:`（测试缝，默认不存在即不生效）。`tools/verify-vba-installed-e2e.ps1` 不传该参数，行为不变。
- 失败文案变化：恢复成功仍含 `previous add-in restored`；恢复失败改为 `ROLLBACK_INCOMPLETE`＋`recovery=`。首次安装失败改为 `first installation rolled back`。任何依赖旧文案的外部解析需要同步（当前仓库内没有此类解析）。
- 新增产品目录临时文件后缀 `.pm-old-<stamp>`（仅存在于运行期间，成功或干净回滚后删除）。`tools/verify-vba-installed-e2e.ps1` 的 `Get-UnrelatedStartupSnapshot` 已按 `PatentMarker.dotm*`／`PatentMarker.addin.install.txt*` 前缀排除，不需要改动。
- 清单内容与格式未变（`product=`／`file=`／`size=`／`installed_at=` 四行 CRLF），`uninstall-vba.vbs` 行为未改。

## 已排除方案

- **在回滚里先删半写入清单再 `MoveFile`**：这正是原缺陷的形态，删除失败时仍会吞错；且无法区分“本次写的残留”与“未知文件”。改为暂存＋归属记录后不需要这个删除。
- **把清单内容写进 dotm 或改用注册表**：超出单包边界，且会改动 `uninstall-vba.vbs` 的所有权协议。
- **引入事务库／日志式回滚**：计划明确不要；最小方案已满足关闭标准。
- **在 `RestoreAddin` 里重新 `CopyFile` 一份旧 dotm**：会产生第二份同名归属物并在磁盘上留下两份恢复源，改用“改名前的 `.pm-old` 参照副本”。

## 残余风险与未覆盖项

1. **真实 Startup 未验证**（L3/L4，协调者负责）。本包全部证据为隔离 Startup 的 L2。
2. **同秒重入**：`.pm-new-`／`.pm-backup-`／`.pm-old-` 用秒级 `Stamp()`，同秒第二次运行会被“staging path already exists”拒绝而非复用。这是保留的既有约定，未改；并发安装未被覆盖。
3. **磁盘满／配额**：`manifest-write` 注入模拟的是 `Err.Raise`，不是真实 `ERROR_DISK_FULL`；真实空间耗尽下的部分写入未被覆盖。
4. **ACL／目录权限拒绝**：未覆盖。注入的是“目标路径被目录占用”，不是 NTFS 拒绝访问。
5. **`fc.exe` 依赖**：字节比较仍用 `cmd /c fc.exe /b`（沿用既有实现）。`fc.exe` 不可用时恢复核对会失败并报 `binary comparison failed`，方向安全（宁可报失败），但会误报为回滚失败。
6. **属性核对只比 ReadOnly／Hidden／System**（掩码 7），不比 Archive；`MoveFile` 实测会保留全部属性位，但 ACL 未核对。
7. **`build.ps1 -Static` 的 release manifest 检查**：5 个 `PatentMarker-*-deploy/PatentMarker-release.txt` 与当前 DLL 不匹配（协调者已在后续统一重建候选包时处理），与 G08 无关。
8. ~~`sync-word-addin.ps1 -Check` 当前非零~~ 已由协调者同步，`-Check` 退出 0。
9. 未覆盖：Word 运行中拒绝安装、卸载器对称性（未改其行为）、32 位 Office、旧版 Word。
